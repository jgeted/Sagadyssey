# 世界模拟 v2：跨系统交互演示

这是一个无依赖的交互演示，用同一件“东区缺粮”事件同时演示人物互动、社会结构、实体经济、运输与战斗。它与当前服务端实现采用同一套原则和术语，但不是 Minecraft 客户端画面的逐像素复制，也不会在演示时修改存档。

## 打开方式

直接双击 `index.html`。演示不访问网络，也不需要构建步骤。

推荐使用 1440×900 或更大的桌面窗口。界面最低支持宽度为 1180 像素。

## 完整演示路径

1. 在“人物”页点击“交谈”，了解玛拉的家庭责任和工坊需要。
2. 可直接“递出面包”；这是一笔世界内赠礼，不打开 NPC 背包。
3. 点击“提出交换”，使用 12 份木炭和 2 枚绿宝石交换玛拉真实拥有的铁锄。
4. 点击“签订护送约定”；只获得北仓—东区路线上的同行与紧急防御授权。
5. 进入“社会”页，查看家庭、行会、议事会与护送契约的重叠关系。
6. 进入“生计”页，接受 #RH-17 委托。北仓实际扣除 24 个面包，货物进入货驴货箱。
7. 演示会切换到“行动”页。选择贴身护送、占据路口或带货撤退。
8. 返回“生计”和“社会”页，查看库存、伤势、履约与关系后果。
9. 点击顶栏“后台真相”，核对精确库存、箭矢、士气、权限与守恒；普通玩家界面不会收到这些字段。

快捷键：人物页使用 `E` 交谈、`G` 递交、`T` 交易、`C` 签约；`Esc` 关闭谈判或调试抽屉。

## 四个界面各自回答什么

| 模块 | 玩家要解决的问题 | 主要视觉形式 |
|---|---|---|
| 人物 | 我认识谁、她愿意告诉我什么、我能做什么 | 场景化人物 + 来源明确的人物志 |
| 社会 | 谁对谁负有义务、资产和权限属于什么制度 | 可选择的关系网络 + 权利边界 |
| 生计 | 物资在哪里、为何短缺、如何移动 | 仓库与运输流图 + 可核对账簿 |
| 行动 | 我知道哪些威胁、凭什么下令、结果是什么 | 战术地图 + 有范围的命令意图 |

四个页面共享一份状态，不是四个孤立 mockup。例如“贴身护送”会消耗 3 支真实箭矢、遗失 1 个面包、给东区增加 23 个面包，并形成家庭和议事会能够传播的履约记录。

人物页现在还提供三张受知识过滤的摘要卡：社会卡只呈现玩家已知的身份和约定，经济卡只呈现可验证需求与真实交换，战斗卡只呈现可观察伤势和有效交战范围。后台仍保存精确库存、权属、债务、伤口、士气、证据与机构权限。

## 视觉与信息原则

- 使用混合式游戏 UI：场景承担气氛和观察，界面叠层承担需要精确判断的条款与库存。
- 每类复杂关系采用不同图形语言，而不是都做成卡片：社会是网络、经济是流、战斗是空间态势。
- 信息按“观察、本人陈述、共同记录、后台真相”分层。
- 颜色只作辅助；节点形状、线型、文字标签和状态描述共同表达含义。
- 高频动作保持一步完成；只有谈判、契约、账簿和调试才展开详细界面。
- 所有示例物品均来自 Minecraft 现有物品。绿宝石是可交易物，不是强制通用货币。

## 自动检查

`smoke-test.cjs` 使用浏览器依次走完整流程并生成五张截图，同时检查控制台错误、交付结果与库存变化。它需要本地 Playwright 和 Chromium/Edge 环境；不属于模组构建流程。

## 原型限制

- 单页 JavaScript 为设计演示方便，同时保存“玩家所知”和“后台真相”。正式实现必须由服务端构建最小披露投影。
- 关系网只演示一小组主体；正式系统应根据玩家知识和当前问题按需裁剪，而不是一次绘制整个世界。
- 战斗使用确定性的三种结果来说明跨系统后果，不代表最终伤害公式或 AI。
- 当前视觉是高分辨率交互方向稿，落入 Minecraft Screen 时仍需换算 GUI scale、输入方式和像素资产。

完整设计见 [世界模拟 v2 总体设计](../../docs/world-simulation-v2/README.md) 与 [战斗、指挥与后果](../../docs/world-simulation-v2/04-combat-and-command.md)。
