# NPC 生活与行动基础层

这套系统不把“职业”直接等同于“每天必须做的事”。职业只描述能力；当前工作由唯一生效的工作权威、工作场所和排班决定。

当前工作权威共有四种：`NONE`、`INSTITUTION`、`PLAYER` 和 `CONTRACT`。普通招募会把权威切换为 `PLAYER`，并暂停原机构岗位、机构仓库和机构订单权限；籍贯、住宅与私人财产不会因此消失。解散后可以恢复原机构岗位。`CONTRACT` 只能由显式外派合同产生，绝不由“已招募”自动推导。

每名固定世界居民持久登记以下信息：出生聚落、原机构工作场所、当前工作权威、当前工作聚落与位置、住宅名称、独占床位、独占私人储物桶、昼夜排班、性格基线、疲劳、最近决定及解释。

行动选择不是固定分数的必然结果。当前休息决策已经采用三个原则：

- 疲劳收益使用边际递减函数，而不是每次固定加分；
- 相对倾向换算为概率，同样状态下允许出现不同选择；
- 决定带有持续时间，避免每 tick 重抽造成抽搐。

固定场景 r7 会为每名居民建立一间小型私人住宅并放置真实床和储物桶。白班居民夜间休息，夜班守卫白天休息，统治者采用弹性排班；遇敌、跟随命令与紧急状态会打断休息。r8 为固定居民加入长期目标、背景记忆和双向人物关系，并把工作、巡逻、保护亲友、休息及撤退接入同一个概率决策器。

r9 新增独立家庭/户籍层。家庭可以包含玩家和 NPC，也可以是亲属、受赡养者、家仆、寄居者或非血亲共同生活者；家庭不会自动变成工作集团、政治封臣或战斗小队。每个人仍拥有自己的床和私人箱，家庭共享储物必须登记为第三种独立的真实容器，不能同时充当私人箱或公共仓库。

农民和矿工的工作区也区分“原机构区域”与“当前区域”。招募会暂停实体上的旧区域，避免 NPC 仍跑回原农田或矿场；解散才恢复。玩家分配新工作地点时，农民得到以目标为中心的 9×9 工作区，矿工得到较大的三维采集区，商人得到市场巡回区，战斗职业得到巡逻中心。

## 玩家分配

先用指挥杖选中属于自己的 NPC，再看向对应方块执行命令：

```text
/saga npc assign bed
/saga npc assign storage
/saga npc assign workplace
/saga npc assign workplace clear
/saga npc shift day
/saga npc shift night
/saga npc shift flexible
```

床和私人储物一次只能给一名 NPC；工作地点和排班可以批量应用到当前选择。公共仓库不能兼任私人储物，双箱也不能作为私人储物，防止所有权重叠。

## 外派合同

站在目标聚落附近，选中自己的 NPC 后执行：

```text
/saga npc contract nearest
/saga npc contract nearest <1-30天> <1-64枚日薪>
/saga npc contract renew <1-30天>
/saga npc contract status
/saga npc contract clear
```

不带参数时默认签订 7 个游戏日、日薪 2 枚绿宝石。只有聚落建立者、当地领主、阵营统治者或管理员可以签发合同。合同保持玩家为唯一指挥方，只额外授予指定聚落设施和物流订单权限；解除或期满后恢复纯玩家直属状态。

工资不是账本数字：系统每个游戏日从签约聚落已登记、已加载的真实仓库中取出绿宝石，再放入 NPC 的私人储物。NPC 没有私人箱、箱子满了或区块没加载时会等待，不视为雇主欠薪；仓库已加载但绿宝石不足才累计欠薪。连续三期欠薪会造成合同违约、士气下降和负面记忆，NPC 对继续工作的倾向也会逐步降低。按时发薪对雇主信任的提升采用边际递减，欠薪则侵蚀长期信任；续期不会清除历史欠薪。到期工资未支付时不能用 `contract clear` 逃避债务，直接解散 NPC 会留下违约记录。

合同与“人物”绑定而不是玩家账号绑定。雇主永久死亡后，其 PLAYER/CONTRACT 工作权威全部结束：NPC 有原机构岗位就恢复原岗位，否则成为无工作权威状态；同一账号的下一世不会继承上一世的雇佣关系。

## 家庭与共享财产

创建家庭后，用指挥杖选中属于自己的 NPC，再为他们登记家庭身份：

```text
/saga household create <家庭名称>
/saga household add spouse
/saga household add child
/saga household add kin
/saga household add dependent
/saga household add servant
/saga household add lodger
/saga household remove
/saga household head
/saga household storage
/saga household storage clear
/saga household inspect
/saga household disband confirm
```

设置共享储物时需要看向二十格以内的单箱、木桶或潜影盒。生产 NPC 在没有可用公共仓库时，约四次入库中有一次会把本批可转移产出的四分之一送入家庭共享储物，其余产出仍进入私人箱；这使家庭积累真实财产，但不会让家庭绕过工作仓库权限。户主死亡时，配偶、子女、亲属、受赡养者、家仆、寄居者依次成为候选继承人；没有幸存者的家庭作为历史户籍保留。

## 饥饿、家庭供给与进食

NPC 的饥饿值会持久保存，范围为 `0-1000`，数值越高越饿。移动和战斗会稍微加快饥饿积累；严重饥饿会缓慢降低士气，但本阶段不会直接用饥饿杀死 NPC。寻找食物与工作、休息、巡逻使用同一个概率决策器，普通饥饿不会机械地在固定数值打断一切，严重饥饿则有很高概率优先处理。

个人进食的物资顺序是：随身背包、私人储物、家庭共享储物。NPC 会走到真实容器旁，真正扣除一件食物并播放进食动作和声音；优先吃熟食，只有严重饥饿时才吃胡萝卜、马铃薯等可能兼作农资的低价值食物。NPC 不会直接吃小麦。

公共仓库由聚落日结系统统一消耗口粮。日结成功后直接满足对应居民的饥饿需求，不会让个人进食 AI 再从公共仓库扣第二份；缺粮时按日期轮换获得完整口粮的人，避免长期固定饿同一批居民。

家庭成员现在也会主动照料彼此。自身饥饿低于 `300`、同户有成员高于 `650` 时，NPC 会结合责任感、社交性、关系、长期目标、当前命令和机会成本作概率判断。有随身熟食时会直接走向家庭共享箱；只有私人箱有熟食时，会先真实取出一件放入背包，再送进共享箱，饥饿成员随后仍需自己走到箱边进食。每户两次主动补给至少间隔 600 tick，避免一次判断把个人存粮全部搬空；中途寻路失败时，食物留在原箱或 NPC 背包中，不会消失。

系统每天记录共享箱食物数、饥饿成员、严重饥饿成员和连续缺粮天数。容器区块未加载时不会把未知库存误判为空。连续缺粮会形成记忆；受赡养者或子女长期得不到食物时，可能逐渐降低对户主供养能力的信心。成功补给则在供养者和受助者之间产生正面记忆与关系变化。

测试时可先用指挥杖选中属于自己的 NPC，或由管理员直接看向二十格内的任意 NPC，再执行：

```text
/saga npc needs hunger 800
```

向其背包、私人箱或家庭共享箱放入面包等食物，即可观察取食。`/saga npc inspect` 会显示当前饥饿值和上次食物来源；`/saga household inspect` 会显示供养状态、连续缺粮、主动贡献次数和共享容器中可直接食用的物品件数。

## 统一日程

NPC 现在持久记录当前日程，而不是让所有 Goal 各自猜测是否该行动。日程状态包括战斗应急、紧急需求、跟随、驻守、排班工作、排班巡逻、回家休息和个人时间。优先级为：战斗目标 → 严重饥饿 → 明确的跟随/驻守命令 → 休息窗口 → 工作或巡逻窗口 → 个人时间。

白班在日出至日落前启动新工作，夜班在傍晚至次日清晨执勤，弹性班覆盖较长白昼；各班的休息窗口仍由私人床行为执行。时间窗口只限制“启动新任务”：已经开始的一次采矿、熔炉操作或实体货运可以安全收尾，运输货物不会因为下班而被瞬移或账本回滚。中度饥饿仍通过概率决策短暂打断工作，严重饥饿则进入紧急需求状态并暂停领取新工作。

看向 NPC 或恰好选中一名自己的 NPC 后执行：

```text
/saga npc schedule
```

该指令显示当前日程、形成原因、排班、玩家命令和下次复核时间。完整的 `/saga npc inspect` 也会显示同样的日程原因。可用原版 `/time set day`、`/time set night` 测试白班工人和夜班守卫，日程最多约 200 tick 后复核，也可再次执行查询立即刷新过期快照。

测试时看向 NPC 后执行：

```text
/saga npc inspect
```

输出会区分归属聚落和当前工作权威，并显示住宅、私人床、私人储物、排班、疲劳、饥饿、上次食物来源、性格、长期目标、重要关系、近期记忆、合同工资/欠薪和最近一次概率决策。私人容器、家庭共享容器与公共仓库在数据和权限上完全分离。
