# 固定小世界：裂冠河谷

`small_realm` 是为超平坦世界设计的首个固定场景。地理布局固定，但政治事件、人物死亡、物流和历史仍由现有动态系统继续推进。

## 内容

- 范围：以生成锚点为中心，半径约 304 格。
- 聚落：河谷镇、麦田村、赤岩矿场、北境堡、灰旗营地、雾月圣所。
- 建筑：16 座，复用现有村庄、民居、铁匠铺、马厩、教堂、城门、瞭望塔和强盗营地模板。
- 地形：缩小后的中央市集、聚落道路，以及两块标准 9×9 农田。每块田由中央一格水湿润全部 80 格耕地。
- 物资：5 个聚落木桶仓库和 2 个近距离市场箱，初始食物、种子、燃料、铁料、绿宝石和箭矢均为实体库存。
- 生产：赤岩矿场提供露天石头、煤矿和铁矿，并设置熔炉、高炉、铁砧与锻造台。赤岩矿工只在矿场工作区内真实采掘并入库，铁匠会从仓库取出原铁和煤，在真实熔炉中冶炼后继续锻造。生产职业进入工作状态时会自动下马；附近没有栅栏也不会阻塞工作。
- 商路：矿业市场与粮食市场相距约 45 格；矿区向村庄运煤、村庄向矿区运小麦，绿宝石反向支付。订单不瞬移物资，商人和运输员必须从箱中取货并亲自携带交付；骑乘者会沿道路运输，受阻时改为牵马步行。
- 居民：20 名固定名称、职业、身份和阵营的 NPC；每个人都有与实体 UUID 相同的永久社会角色档案。守卫、士兵和强盗会在各自聚落内巡逻。
- 局势：王位明确空缺，由王廷总管维持河谷；王国与强盗处于战争状态，商人行会与王国友好。
- 封建关系：总管、村长、守将、灰旗头目和司祭持有各自聚落头衔；村长与守将向总管效忠，卫队长、弓手和医师向本地领主效忠。

场景只生成有限区域，不修改世界边界，也不会阻止玩家继续探索超平坦世界的其他区域。

## 使用方法

1. 创建允许作弊的超平坦世界。
2. 站在希望作为河谷镇中心的位置。锚点会自动对齐到当前区块的西北角，并使用脚下地表高度。
3. 执行 `/saga scenario preview small_realm`。蓝色粒子表示场景边界，金色粒子表示聚落中心，绿色粒子表示农民的固定工作区。
4. 确认区域后执行 `/saga scenario generate small_realm`。
5. 使用 `/saga scenario status` 查看分批生成进度。
6. 完成后执行 `/saga scenario verify`，检查农田水源、80 格耕地、围栏、建筑登记、结构方块、仓库和已加载 NPC。
7. 再执行 `/saga audit` 检查角色、政治、聚落、仓库、订单和事件引用。
8. 看向 NPC 执行 `/saga npc inspect`，可查看当前任务与目标、最近失败原因、背包用量、铁匠炉内状态、运输订单、所属聚落、工作区以及最近可用仓库；绿色粒子会指向该仓库。
9. 执行 `/saga logistics warehouses` 查看全部仓库，再用 `/saga logistics locate <仓库UUID>` 标出指定仓库。
10. 执行 `/saga scenario observe` 查看离玩家最近场景的 NPC 当前动作、背包、独立运输货舱、私人床箱、仓库库存、炉内物品和物流订单；彩色粒子柱会标出对象位置。
11. 旧测试世界若留有成堆农产品或矿物，先执行 `/saga scenario reclaim-drops preview`；确认统计无误后再执行 `/saga scenario reclaim-drops confirm` 入库。工具、装备及非白名单物品不会被处理。
12. 饥饿测试可用指挥杖选中自己的 NPC，或直接看向任意 NPC，执行 `/saga npc needs hunger 800`，再向其背包、私人箱或家庭共享箱放入面包；用 `/saga npc inspect` 查看取食来源。公共聚落居民的仓库口粮由每日结算统一供给。
13. 家庭照料测试可把同户一名 NPC 的饥饿设为 `900`、另一名设为 `0`，在温饱成员的背包或私人箱放入面包并清空家庭共享箱；温饱成员会概率性地把一份食物送入共享箱。`/saga household inspect` 会显示贡献次数和缺粮状态。
14. 日程测试先执行 `/time set day`，查看白班工人和农民的 `/saga npc schedule`；再执行 `/time set night`，白班居民应进入休息状态，夜班守卫进入排班巡逻。严重饥饿会覆盖普通日程，但不会覆盖正在发生的战斗。

可用命令：

- `/saga scenario list`
- `/saga scenario preview small_realm`
- `/saga scenario generate small_realm`
- `/saga scenario generate small_realm force`
- `/saga scenario status`
- `/saga scenario observe`
- `/saga scenario test profiles`
- `/saga scenario test reset <profile>`
- `/saga scenario verify`
- `/saga scenario repair confirm`
- `/saga scenario reclaim-drops preview`
- `/saga scenario reclaim-drops confirm`
- `/saga scenario cancel`
- `/saga npc inspect`
- `/saga npc needs hunger <0-1000>`（管理员测试命令）
- `/saga npc schedule`
- `/saga logistics warehouses`
- `/saga logistics orders`
- `/saga logistics locate <warehouse_id>`
- `/saga verifier snapshot <name>`（管理员，只读记录当前后台摘要）
- `/saga verifier diff <name>`（管理员，与会话内快照比较）
- `/saga verifier conservation <name>`（管理员，核对已捕获物品总量变化）

`generate`、`verify`、`repair` 与 `cancel` 需要管理员权限。普通世界默认拒绝生成；`force` 可绕过世界类型、区域占用和重复部署保护，因此只适合已备份的测试世界。

## 独立职业实验场

八个实验场都按超平坦世界设计，半径为 64 格，不放置 NBT 建筑模板，所以不会生成结构方块。它们仍会为每名 NPC 建立可使用的独立小屋、私人床和私人储物桶。生成完成后会自动套用默认测试档；站在实验场附近执行 `observe` 或 `test reset` 时，命令总是选择离玩家最近的实验场。

统一测试顺序：

1. `/time set day`
2. `/gamerule doDaylightCycle false`
3. `/saga scenario generate <场景ID>`
4. 等待完成后执行 `/saga scenario verify`
5. `/saga scenario observe`
6. 若要重复或切换子测试：`/saga scenario test profiles`，再执行 `/saga scenario test reset <档位>`

实验 NPC 一旦被玩家招募或签订个人契约，`test reset` 会整体拒绝执行，以免清空玩家管理的物资、命令和在途货物。请保留一份未招募的实验 NPC 用于可重复测试。

场景与测试档：

| 场景 ID | 默认档 | 可切换档位 | 主要观察点 |
| --- | --- | --- | --- |
| `blacksmith_lab` | `smelt` | `smelt` / `forge` / `repair` | 原料箱减少，炉输入和燃料变化，铁锭进入背包，工具生成或耐久恢复 |
| `farmer_lab` | `harvest` | `harvest` / `sow` / `irrigate` | 9×9 农田中央一格水；收获、播种与农民自行放水分别独立复现 |
| `worker_lab` | `mine` | `mine` / `overhead` / `logging` | 正面矿墙、高处矿物临时垫脚、整列砍树与产物入库 |
| `trader_lab` | `logistics` | `logistics` / `route` | 两箱相距 20 格；真实煤/小麦订单或无订单市场巡回 |
| `guard_lab` | `patrol` | `patrol` / `combat` | 无敌人时巡逻；战斗档在警戒圈内生成一只具名训练僵尸 |
| `medic_lab` | `treat` | `treat` / `healthy` | 消耗白色羊毛治疗三成生命盟友；满血档应保持无治疗 |
| `bard_lab` | `perform` | `perform` | 演奏动作、音符粒子以及两名听众的士气增长 |
| `household_lab` | `care` | `care` / `sleep` | 家庭食物援助；`sleep` 后执行 `/time set night` 观察各自回私人床 |

一个世界里可以放多个实验场，但两个半径 64 的实验场中心至少应相距 160 格。为了让录像和定位最简单，首轮测试建议每个新世界只生成一个实验场。

`repair confirm` 会在原锚点重铺当前定义覆盖的道路、农田和矿场，重新放置建筑、精确清除模板原有结构标记，并纠正未招募 NPC 的固定工作配置。它不会复活死亡或当前未加载的旧 NPC，不会夺回玩家已经招募的 NPC，也不会重置 NPC 的经验、身份、阵营以及世界已经演变的政治关系。r4 修复会新增赤岩矿场、两个测试市场箱和新居民，并让未招募的商人、运输员、工人、铁匠及战斗 NPC 进入新增岗位；r5 会把原“村中樵夫”纠正为赤岩矿工并绑定矿场工作区；r6 引入可站立工作点、骑乘物流回退、生产背压及安全掉落物回收。旧于 r3 的场景还会补建具名 NPC 的角色档案和初始封建关系；r3 之后不会重置已经演变的头衔与效忠关系。仍然存在的已登记仓库不会重置库存；仓库容器被破坏时才会重建并补回初始库存。该操作会覆盖玩家对场景建筑的改造，所以必须显式输入 `confirm`。

场景定义带有持久化修订号。`/saga scenario status` 会显示部署修订；旧存档显示例如 `r2→r3` 时，表示可以备份后运行修复。新生成和修复完成时都会自动执行一次结构验收。

## 生成机制

任务依次执行以下阶段：

1. 使用确定性 UUID 登记聚落。
2. 每 tick 最多修改 384 个道路、广场或农田方块；农田会生成围栏、北门、堆肥桶和中央水源。
3. 每 tick 放置一座 NBT 建筑，并登记到指定聚落。结构方块和模板内实体不会进入世界。
4. 放置真实木桶或箱子仓库并填入初始实体库存。
5. 每 tick 最多生成 4 名持久化 NPC，并以实体 UUID 登记其永久人物档案。
6. 授予聚落头衔、建立初始封臣关系、宣布王位空缺，再建立阵营关系并写入世界编年史。

任务阶段和游标写入世界 SavedData。服务器在生成过程中关闭后，下次启动会从当前阶段继续。模板、聚落和 NPC 使用确定性标识，重试不会正常地产生重复对象。

## 安全限制

- 同一维度同时只能执行一个部署任务。
- 默认检查真实模板旋转后的边界，检测到玩家建筑会拒绝生成。
- 已有场景之间保留额外 32 格安全距离。
- `cancel` 只停止后续步骤，不回滚已经放置的方块或实体。
- 不使用异步世界写入，也不长期强制加载场景区块。
- 场景生成不会自动把执行命令的管理员设为建立者、领主或 NPC 主人。
- 具名 NPC 死亡后人物档案永久保留，头衔会按指定继承人转移；没有有效继承人时头衔变为空缺。重新生成或修复不会复活该人物。
- 两名麦田村农民分别绑定一块 9×9 农田，不能在马场或道路上翻地。
- 两名麦田农民固定使用“农作物”模式；补种时优先沿用相邻作物，因此这两块初始麦田会继续补种小麦，不会自行混入瓜类或甘蔗。
- 自动贸易只在两个市场区块已加载时发布需求，不会为了后台贸易长期强制加载地图。
- 机构商人运输时会向 64 格内的玩家显示短距离彩色方向粒子，并在取货、交货时显示动作栏消息；不会向全服广播。
- 生产者背包接近满载时会优先入库；仓库不可用时暂停破坏方块。新产生的溢出物带来源标记，只允许原 NPC 自动捡回。
- 地面物资回收指令只处理当前已加载区块内的农产品、原木和矿物白名单，并且必须先预览再由管理员确认。
- 巡逻 NPC 的自主索敌和追击受驻地半径约束，附近史莱姆不会把整支守军持续带离聚落。
- 玩家普通招募固定居民后，原聚落岗位与机构仓库权限立即暂停，当前工作权威唯一切换为玩家；籍贯、历史与私人财产仍然保留。解散后才恢复原机构岗位。以后只有单独签订的外派合同可以例外地授权指定机构设施；普通招募不等同于合同。没有机构岗位的玩家铁匠仍能使用随身原料和附近熔炉。
- r7 起每位固定居民都会登记独立住宅、私人床、私人储物桶、原岗位、当前工作场所与昼夜排班。r8 继续加入长期目标、背景记忆、亲属/朋友/师徒/竞争关系和统一概率决策。`/saga npc inspect` 会显示这些信息并用粒子指向床位和可用仓库。
- r9 将麦田村长与一名近亲登记为“麦穗之家”，并把雾月司祭和医师登记为非血亲共同生活户；两户各有独立实体共享储物，不与私人箱或公共仓库混用。
- 旧测试世界可以用 `/saga scenario repair confirm` 修复当前场景占用位置和结构标记；旧版本曾生成、但新版定义已不再包含的外围方块不会被猜测性删除。
- 要验证完全干净的新版布局，仍建议使用新的超平坦测试世界。
