# 阶段 10：LOD、预算与显式迁移

状态：2026-10-07 23:31 已完成并结项。旧完整世界副本迁移/重进/回滚及真人卸载/返回、保存退出重进均通过；完整证据与覆盖边界见 [验收记录](10-phase10-acceptance.md)。

## 分层与对账

| 层级 | 推进方式 | 禁止事项 |
|---|---|---|
| L0 实体 | 原身体执行计划，真实移动、劳动、消费与交付 | 不从摘要生成替代人物或物品 |
| L1 区域/离线 | 卸载检查点按到期队列推进休息基础饥饿，每 200 刻 +2 | 不把离线时间当锻造、治疗、采集、教学或运输劳动 |
| L2 聚落 | 分批执行原聚落事件；口粮仍读取实际已加载仓库与居民 | 未加载仓库不凭账面数扣料或发粮 |
| L3 世界 | 单调 gameTime + 一次性旧时钟偏移，沿用原事件与剩余期限 | `/time set` 不重放/跳过已经提交的世界日事件 |

`sagadyssey_npc_lod_v3` 保留身体/人物 UUID、维度/位置、原计划 UUID/内容修订、最后连续成功步骤、资产与实际劳动修订、原订单修订、预留标识、完整槽位/组件指纹和摘要时间。不保存可恢复的物品副本或第二份可执行计划。

真实区块卸载时只清理进程内执行器、导航与感知引用；持久携货义务和未消费的物资仍属于原记录。实体加入时，在任何 Goal 或领域服务转移货物之前完成对账；NoAI 原实体也注册为已加载，不能同时被 L1 当作离线人物推进。正常服务端停止前保存最终提交边界。

库存/计划不一致、身份重绑定、步骤或修订倒退时进入 `REVIEW`，暂停计划，不回填旧库存。外部合法订单/权限/目标变化由原执行器重新验证，不能仅凭旧摘要继续作业。损坏/未知 schema 不允许静默替换为空数据。

## 预算和监控

后台入口：`/saga lod status`，权限等级 2；普通 NPC 交互投影没有新增 LOD 真值。
状态首行包含 `已卸载` 检查点数量；真人离开场地时必须实际增加，不能把距离当作已经卸载的证明。

| 项目 | 每 tick 上限 | 边界 |
|---|---|---|
| 新任务选择 | 8 次，软时间 2 ms，FIFO 容量 8192 | 已执行步骤与严重饥饿不饿死在选择队列里 |
| 农田/采集目标发现 | 每次最多 512 格、软时间 0.25 ms | 完整探测之间让出，持久游标继续；不缩小工作区、不跳过远处目标 |
| 自主附近敌人扫描 | 12 次，软时间 1 ms，FIFO 容量 8192 | 直接受击/原发令人遇袭的紧急来源不延迟；缓存仍核验存活/距离/视线 |
| 计划步行寻路提交 | 8 次，软时间 2 ms，FIFO 容量 8192 | 过期计划/步骤/命令请求拒绝；入队不等于抵达 |
| L1 摘要 | 8 个到期检查点 | 按到期索引，不逐 tick 扫描全部离线人物 |
| 聚落事件 | 4 个，软时间 1 ms | 尚未实际处理的结算保持到期状态 |
| NPC 普通上下文载荷 | 单包/单玩家每 tick 64 KiB，全服每 tick 512 KiB | 仅此载荷；不冒充原版、全模组网络总预算 |

时间预算不能抢占已经开始的一次 Java 调用，因此是软上限；硬次数/字节上限仍严格执行。已存在的战斗、原版寻路推进、坐骑及所有活动执行器并未统统挪入一个全局时间切片。监控记录完整主线程 tick、选择、感知、寻路、离线/聚落/世界事件和实际编码载荷；每类最多保留 4096 个近期样本，最大值覆盖该轮全部调用。P95 不能被解释为全部历史采样的 P95。

检查点容量 8192、迁移日志容量 64；满时拒绝，不静默清理历史。显式归档仍需管理者保留完整证据，不承诺生产世界无限容量。

完整主线程 tick 另记录本轮超过 50 ms 的总次数和最近 64 个慢 tick 的模拟时刻，不只看近期 P95。三日场景允许最多 3 个孤立慢 tick，但不等于证明所有负载下都没有周期性卡顿；原始计数与最大值必须在验收记录中披露。JFR 在预热结束前启动，测量结束后落盘，录制启动/落盘本身不混入 72000 刻测量窗；落盘后的 tick 仍可能在服务器日志中显示耗时。

## 旧存档灰度迁移

遵循总计划 §12：未选择迁移的旧人物默认 LEGACY，不全局停工。PLANNED 的旧职业 Goal 不执行、不结算；新系统只读取旧字段作兼容输入，迁移不会让新旧工作系统同时扣料。

1. 正常退出后备份完整世界，包括区块/实体、玩家、全部 SavedData；不要只备份某个 `.dat`。
2. 在**副本**加载所选原人物，先停稳旧行为，推荐显式 NoAI；保留原身份、槽位、组件和旧领域记录。先一名，再聚落范围。不要用新 NPC 替换旧人物。
3. `/saga lod migration dryrun <所选原NPC选择器>` 返回稳定 revision，以及原身体/人物数、持有物品总件数、关联生产订单数、活动计划数。范围为 1–100 名已加载原人物，不包含未加载仓库；dry-run 不切模式、不扣料、不生成订单。
4. `/saga lod migration apply <revision> <同一选择器>` 做修订比较；原记录已变化就拒绝，先重做 dry-run。写入并保存 INTENT 后再变更模式，随后保存 APPLIED 回执。不会复制物资、重建人物或凭空创建旧工作订单。
5. `/saga lod migration report <receipt>` 查询持久的迁移前后数量、原身份、修订和状态；立即核对原人物/物品/计划。正常退出重进同一副本核对。未选人物仍 LEGACY。需要恢复 AI 时明确解除自己设置的 NoAI，不由迁移偷偷改动。

`/saga lod migration rollback <receipt>` 仅接受 APPLIED、全部原身体加载、尚无活动计划、迁移后整体修订未改变的记录；只还原兼容模式并移除该批 LOD 检查点，保留回滚回执，不恢复任何旧物资快照。已发生劳动/移动/资产变化或遇到不确定 INTENT 时，拒绝局部回滚；恢复一致的完整世界备份。不能声称跨多个 SavedData 在所有断电点都有原子事务。

冻结 v1.9 工人/农民/铁匠夹具只含 SavedData，不含旧区块、玩家或实体文件。自动测试实际调用十个领域的反序列化器和保存器，比较重复迁移的稳定结果；另用真实 LEGACY 原实体、带组件物品和独立 JVM 验证显式迁移/回滚。两类证据不能合称为“冻结旧世界全部实体与 Research 的真人迁移已验收”。

经用户明确授权，`scripts/verify-phase10-world-copy.ps1` 另将 `阶段7教堂测试` 的全部 64 个文件复制至唯一新目录，用**正常服务器**加载完整旧世界（不用会替换世界设置的 GameTestServer）。原人物在副本中明确暂停，选原铁匠/工人/农民三名 LEGACY 空闲身体做 dry-run/apply，同一副本独立 JVM 重进，再第三个进程安全 rollback；最后恢复原 NoAI 和原强制加载状态。服务端仅绑定 127.0.0.1 随机端口；未手写接受 EULA，开发运行时沿用原版 IDE 行为。

离线工具 `scripts/inspect_phase10_copy.py` 实际读取实体/方块 region NBT，对照全部 33 个原 NPC 身份及带组件库存、756 个原容器槽位、玩家原文件和已有领域的顶层记录数量。源世界全文件 SHA256 前后相同。该世界 Research 记录为空，合同方面实际对照 5 条服务关系；不能声称证明非空 Research 或所有合同场景。迁移检查原始快照仅存在副本的验收输入文件，不是生产 LOD 检查点，不被用来恢复物品或替换人物。

验收发现并修复旧加载入口的坐骑重复生成：`VehicleEventHandler.onNpcSpawn` 必须在 `loadedFromDisk` 时直接返回，不能对旧身体再次随机配马/马鞍/缰绳。GameTest 在出生概率 100% 时验证磁盘加入不配新坐骑、不改原库存；正常新生 NPC 的概率行为保留。

通过的副本另复制到客户端 `phase10-client-<唯一编号>` 文件夹，完整哈希一致后写入 `build/reports/phase10/client-launch.clixml`。`Start-Phase10-Acceptance.cmd` 仅接受这一受限目录名并校验回执/level.dat，使用原版 `--quickPlaySingleplayer` 直达副本；启动失败不回退打开原世界。`-Check` 只检查 Java/目录，不冒充 GUI 运行证据。
