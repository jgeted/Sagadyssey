# 近处食物链路验收（2026-10-19）

本轮完成有明确设施和权限配置的近处链路验收：原居民作业、作物生长、收获补种、产出入库、原版熔炉加工、家庭匹配、原运输者搬运、实际进食、短缺反馈、实际卸载恢复和独立进程重启核对。复用现有行为、产权、需求、物流及恢复系统，只修正一处私人空仓/原料仓阻挡家庭取食的运行时接入问题。

这份报告接续 `local-stock-reconciliation.md` 的家庭替代食物增量。此前 74 项相关单元测试和 32 项游戏测试的原始记录仍保留。最后这处修改后，实际重新通过 186 项相关单元测试、32 项家庭补给游戏测试、6 项定向生活游戏测试；不与旧结果相加冒充全仓覆盖。

## 验收设施与边界

- 作业者为真实计划模式农民；家庭成员为真实计划模式运输者。没有注入生产、交付或进食完成回执。
- 初始随身储备为 16 个种薯，田里另有一株零龄土豆。明确配置耕地、水源、光照、私人入库桶、漏斗、熔炉、成品桶和家庭粮仓；农民使用正式私人储物登记，不使用 testStorage 覆盖。
- 通过原版 CropBlock.randomTick 推进生长，每 5 个游戏刻至多调用一次，不直接设置成熟年龄；因此验证完整生长规则和生产周期，不能解释为默认随机刻速率下的产量或长期人口承载量。
- 烤土豆使用原版真实熔炉、配方、燃料和漏斗转移。这里支持的是预先配置的加工设施；NPC 自建加工线、通用食品配方与自主补燃料并未由本轮新增。
- 普通储物接口仍只接受支持的储物容器。初始夹具将漏斗作为私人仓库会受阻，已改用正式储物桶接漏斗，没有扩大容器白名单。
- 已知成品来源按原权限登记；家庭取得明确 TRANSFER 授权，匹配、预留、取货和消费仍走正式服务。没有让未知或无权来源参与供给。

### 连续三个游戏日与最小阻塞修复

进一步将原农民加入同一真实家庭，两人的初始饥饿均为 340，家庭储备目标为 4，配置 64 个煤作为本轮初始燃料预算，期间不补入任何食物或燃料。按每 100 刻至多一次原版生长调用，连续观察 72000 个游戏刻。

实施前定向复现确认：私人仓库已登记但为空时，LifePlanProvider 仍选 PRIVATE，遮挡家庭粮仓中的实际熟食。仅修改 LifePlanProvider：选择私人食物前，先在已知、已加载且受支持的私人容器中观察是否存在当前饥饿程度可以消费的食物；否则继续原有家庭来源选择。权限和预留仍由原执行器在真实消费时复核，没有新增权限或消费事务。

复现日志 `selection-red2.log` 的目标断言实际失败；修复后 `selection-green.log` 和最终生活回归中的同一用例通过。连续最终运行 `continuous-final.log` 实测：3 次收获、3 次补种、净产出土豆 9 个、实际烤制 9 个；农民与运输者各完成 3 次真实进食，剩余熟食 3 个、生种薯 16 个、煤 62 个，两人的最终饥饿均为 38。全部原料、配方转换、实物和完成的进食回执对应。计划历史只保留最近 32 条，因此测试持续收集已经完成的原生活回执标识后去重计数，不把末尾有限历史误当全周期总消费。

首次连续试验的三轮收获已发生，但测试额外写入了“四次收获”的假定数量，因而失败。验收修正为既定的重复完整周期、足量真实消费、饥饿和物资守恒；没有改变作物生长率或生产数量来凑出第四轮。最终独立新世界再次运行满三日并验证全部守恒断言通过。

本次形成的是三日、有明确设施与燃料预算的连续供给证据，不能外推为默认生长速率下的无限期自给或任意人口的承载能力。

恢复夹具读取最终 `level.dat` 时钟。GameTestServer 会重置自身时钟，而聚落测试已推进到后续日结；仅回到中途检查点时间会使后写入的 LOD 摘要遇到时间倒退。该问题修正在测试启动器内，没有放宽生产恢复规则。恢复时允许检查点之后真实经过的时间造成饥饿增长，不要求几天后仍维持刚进食时的饥饿值。

## 对账口径

- 土豆：`初始随身16 + 田间回执净变化 = 所有节点生土豆 + 实际熔炉配方完成数`。田间净变化包括收获正数与补种负数，原有种薯不算新增产出。
- 熟食：`熔炉配方完成数 = 所有节点烤土豆 + 有原生活回执的实际进食数`。
- 实物节点包含农民随身、运输者随身与货舱、入库桶、输入漏斗、熔炉、输出漏斗、成品桶及家庭粮仓。需求预留、在途计数不再作为额外实物相加。
- 检查点只能在原生产和补给已结清、没有 pending 或 REVIEW、所有新增土豆加工完毕后保存；保存后恢复核对同一批实物和回执。
- 聚落口粮按自身原有小麦抽象制粮规则单独核对，不把抽象口粮当作家庭实体熟食，也不替代家庭运输消费验收。
