## 兼容性和故障边界

- 异常数据加载目前采用整个受影响账本拒绝加载，保留原文件并提示恢复；没有实现坏记录隔离后继续运行其余记录，也没有自动还原丢失的数据。正常世界读取已用针对性的旧数据单元测试验证。
- 不含 RequestIdentity 的旧转移回执继续沿用原重放行为，防止已经执行的实物转移被再次执行；不会将新提交的内容追认成历史证据。因此旧回执的内容冲突检测仍是已知边界。
- 请求身份中仍使用现有 ItemFingerprint；其组件哈希碰撞风险未因增加请求身份 NBT 而消失。
- 补给发布保证的是当前服务器线程内可预见异常的状态一致性，不是多个 SavedData 文件在进程崩溃、断电时的磁盘原子事务。此前已损坏或已形成孤立状态的账本不会被本轮自动改写。
- 没有改变当前职业选择优先级、固定生产订单、已经在途的补给义务、人物身份和原有测试世界。
