# 阶段 6：需求—生产—运输闭环

状态：2026-10-04 完成。346 项自动化测试、完整构建和两个独立进程中各 68 项真实游戏场景全部通过。验收记录见 [06-phase6-acceptance.md](06-phase6-acceptance.md)。未进入阶段 7。

## 持久需求与资产边界

新增服务端 `social.needs` 领域，不接入普通玩家界面，不自动切换 NPC 模式。

- `NeedRequestStatus`：履约、外部等待、不可达、循环阻塞和终态约束。
- `NeedRequest`：主体、用途、精确物品指纹、目标容器、有效时间窗作为去重身份；保留原始数量和当前数量；分别记载已预留、在途、已交付以及尚未承诺数量。
- `NeedRequestData`：世界级需求存档；同键更新数量，不新建请求；持久回执去重，拒绝同一回执换用途或换请求；依赖图自环/循环检测；容量达到上限时拒绝继续追加，不静默淘汰活动请求或回执。
- 到期或重试预算耗尽禁止新增预留，但允许真实在途货物后续交付。取消前必须释放预留并核对在途货物，不能清空货物计数来假装取消成功。
- 存档字段、重复身份、重复回执、循环图严格校验；已有账本不可读时停止并要求恢复，不能用空账本替代。

回执接口只登记已经被资产服务确认的操作；自身不移动物品，不证明权限，也不保证与资产账本跨文件硬崩溃原子提交。执行器核对真实资产预留与 `TransferService` 回执，不能直接依赖需求计数创造物资。

`SupplyFlowData` 保存供给地点、按主体隔离的已知地点、家庭/作坊/机构储备策略、需求与生产订单的关联，以及固定身份的运输单和待提交转移意图。地点知识不等于处分权；既有权属不能被地点登记覆盖。仓库、家庭储物、私人储物的既有容器身份由 `ProductionContainerIds` 统一解析，避免同一物理容器出现第二套资产账本。

## 聚合、库存匹配和生产

- 家庭按真实共享储物中的食品、燃料、可用工具计算缺口；用人物身份识别 PLANNED 家庭成员，不误用实体 UUID。
- 作坊和机构按显式储备目标聚合真实库存缺口；同用途活动请求更新数量，不逐次创建新单。到期且没有预留/在途货物时，重新核对实物后进入新的时间窗。
- 原有生产缺料请求桥接到持久需求，保留旧生产接口兼容。机构仅学习自身注册设施，不扫描无关仓库。
- 匹配只读取已知、已加载、同维度、具有真实处分权的库存；核验精确物品组件、声明数量、负担和其他预留，先预留再生成物流单。
- 第一条自动制造配方为铁镐：缺成品且存在真实锻造设施时形成生产单；缺铁、煤则形成依赖需求和运输单；实际批次完成、成品入库后才登记履约。输入交付在原生产批次完成后标记已消费。
- 其他没有已实现制造配方的缺货进入 `WAITING_EXTERNAL`；外部等待有限退避，不按每 tick 反复创建订单。晚于需求期限完成的生产批次保留实物和回执供核对，不强行修改过期需求或制造第二份成品。

## 真实运输与商人

- `SupplyTransportTask`：领取唯一任务 → 实际走到源容器 → 原子取货 → 真实货舱携带 → 实际走到目标 → 原子交付 → 有限休整/下一任务。采用分段导航，不受 NPC 周围 20 格检索限制，不远程履约。
- 运输单分别绑定实体和人物身份，两名运输者不能领取同一批货。取货前重新核对工作权威；已经携带的原义务在服务关系结束后仍保留。
- 目标满、不可达、权属变化或明确暂停不删除货物。连续路径失败结束有限计划并退避；取货前终止释放预留，取货后保留在途义务。运输者死亡时掉落实体货物，并登记待核对，不伪造交付。
- `LogisticsOrderRecord` 增加精确组件和关联需求；旧物流 Goal 不领取或取消新需求管理的订单。旧物流和商人移动 Goal 在 PLANNED 模式下隔离。
- `MerchantSupplyData` 保存持有者真实报价、每名商人独立的供需观察、路线、买入和卖出回执；候选只使用自身已知信息，不远程读取未知聚落的库存。
- `MerchantSupplyTask` 用真实绿宝石支付、将货物放入真实货舱、走到另一个已知市场，再以货物换取真实付款。钱与货的多腿转移整体检查权限、库存、容量和修订号；未成交不登记利润，满仓和重载不重复扣钱或买入。

## 保存恢复、后台与验证

新执行器仅对显式 PLANNED 模式和允许工作状态运行，不批量改写旧角色。所有新增存档严格核验字段、重复身份、孤立关联和容量；损坏既有账本不会被空账本覆盖。

每次转移先保存固定请求身份与载荷；正常保存重载查同一回执再恢复步骤。缺少可验证回执的不确定硬中断进入 `REVIEW`，不自动重放。正常存档恢复和新进程续运已通过，但不宣称多个 SavedData 与实体区块在突然断电时具有跨文件原子性。

普通玩家投影不增加精确需求、供给地点、隐藏库存、路线或回执。权限 2 后台入口：

- `/saga supply audit`：需求数量、状态、原因、运输关联与商人买卖回执。
- `/saga supply know-source <npc> <place>`：明确告知一个储物地点，保留既有权属，不赠送物品或处分权。
- `/saga supply buffer <npc> <category> <item> <quantity> <place>`：登记真实储备目标，类别为 `household` / `workshop` / `institution`；此便捷入口的目标须归指定 NPC，机构/家庭策略另由相应主体注册。
- `/saga supply quote <sell|buy> <item> <price> <quantity> <settlement UUID> <place>`：测试者代持有者声明报价；必须先有真实容器及权属，不生成商品或钱。
- `/saga supply learn-quote <npc> <quote UUID> <observedQuantity>`：明确向此商人传达观察；抵达后仍核对真实库存、付款和权限。
- `/saga supply cancel <need UUID>`：取货前释放预留再取消；在途/不确定交付不得清空义务。
