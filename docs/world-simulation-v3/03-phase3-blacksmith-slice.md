# 阶段 3：铁匠纵向切片实施契约

## 1. 目标

第一条真实计划只处理明确的生产单或维修单，不允许铁匠因“空闲且包里有材料”自动无限制造工具。

```text
生产单
→ 核验订单、权限、原料、输出空间和工作站
→ 预留资产、输出槽和工作站
→ 前往工作站
→ 播放一次完整锻造动作并累计劳动
→ 幂等结算生产批次
→ 把成品交到订单指定位置
→ 完成订单、释放预留、重新规划
```

缺铁、缺煤、工作站忙、输出满或目标不可达都必须进入结构化 `BLOCKED`，不得播放锻造动作。

## 2. 固定步骤

每个订单从创建起固定 `orderId`、`batchId`、配方、投入、产出、劳动时长、工作站和目标容器；每个计划步骤都保存 `orderId`、`batchId` 与劳动时长，位置步骤另外保存维度和坐标。

| 阶段 | 执行器 | 可修改内容 |
|---|---|---|
| `RESERVING` | `blacksmith_reserve_order` | 领取订单；核验并预留原料、工作站、输出槽 |
| `TRAVELLING` | `move_to_block` | 只导航，不生产、不消费原料 |
| `ACTING` | `blacksmith_forge` | 只累计劳动并触发一次动作 |
| `SETTLING` | `blacksmith_settle` | 调用幂等生产结算与真实交付 |

执行器重载恢复必须重新核验资源。持久化为 `RUNNING` 的步骤先走 `recover`，不能直接 `tick`。

## 3. 已先行修正的生产边界

- `ProductionService.begin` 支持计划预先生成的固定 `batchId`；
- 同一个批次 ID 和同一个生产意图重复提交会返回原批次；
- 同一个批次 ID 被不同意图复用会拒绝；
- 已完成批次再次 `complete` 直接返回原回执，不重复扣料或产出；
- 输出没有空位时抛出可重试的 `ProductionBlockedException(OUTPUT_FULL)`，批次和原料预留保持有效；
- NPC 持久化 `ActionStartCount`，可验证一张生产单只启动一次锻造动作。

## 4. 当前实现

1. `ProductionOrderData` 持久保存订单、固定批次 ID、劳动需求、分配工人、工作站、目标容器、阻塞原因和严格状态转换；
2. 工作站和目标容器使用计划级互斥预留；服务重载后执行器会按同一计划 ID 重抢；
3. `ProductionService` 会恢复过期的资产预留，同一批次重复开始/完成不会重复扣料或产出；
4. `blacksmith_reserve_order → move_to_block → blacksmith_forge → blacksmith_settle` 已注册到实体执行桥；
5. 动作开始前先持久化 `IN_PROGRESS`，重载进入 `recover` 后不重播动作；
6. `/saga npc brain seed-blacksmith` 可生成真实铁镐订单，`orders`、`inspect`、`reservations` 提供后台真值；
7. 自动化 229 项全部通过；游戏内缺料、输出满、竞争与中途重载仍需按下述流程验收；
8. 计划内部失败会关闭订单、批次和缺料请求，产出叠堆不会借“转移权”覆盖他人物品所有权，新注册仓库也沿用稳定物理容器 ID。

未显式切为 `PLANNED` 的 NPC 仍运行旧行为。测试命令只切换目标铁匠，不会全局迁移存档。

## 5. 自动化验收

- 缺煤时计划阻塞、请求只有一条、动作和结算均为零；
- 煤到货后恢复同一个计划 ID，动作一次、结算一次；
- 两名铁匠竞争同一工作站时最多一人进入 `ACTING`；
- 输出满时不消耗原料、不播放动作，清出空间后恢复；
- `ACTING` 重载后调用 `recover`，不再次调用 `start`；
- 结算完成但计划快照尚未更新时重载，不重复产出；
- 计划终态后没有工作站、输出槽或资产预留；
- 同一订单完成后 Provider 不再生成候选。

## 6. 游戏内验收流程

先放置工作站和容器（坐标可换成绝对坐标），并让最近的 NPC 是铁匠、命令状态为“工作”：

```mcfunction
/setblock ~2 ~ ~ minecraft:anvil
/setblock ~4 ~ ~ minecraft:barrel
```

在木桶中放入 3 个铁锭、1 个煤炭，并至少留一个空槽，然后执行：

```mcfunction
/saga npc brain seed-blacksmith @e[type=sagadyssey:npc_base,sort=nearest,limit=1] ~2 ~ ~ ~4 ~ ~
/saga npc brain inspect @e[type=sagadyssey:npc_base,sort=nearest,limit=1]
/saga npc brain orders @e[type=sagadyssey:npc_base,sort=nearest,limit=1]
/saga npc brain reservations @e[type=sagadyssey:npc_base,sort=nearest,limit=1]
```

预期：铁匠先取得两项互斥预留，走到铁砧，只启动一次 `SMITH` 动作，80 tick 后木桶减少 3 铁锭和 1 煤炭并新增 1 铁镐；订单与计划均成功，互斥预留归零。

边界测试：

- 缺煤：只放 3 铁锭创建订单；订单显示 `MISSING_INPUT`，动作计数不增加。补入煤炭后最多 100 tick 恢复同一订单和批次；
- 输出满：把木桶所有槽占满再创建；订单显示 `OUTPUT_FULL`，原料不减少。清出一格后恢复；
- 保存重载：动作开始后立刻退出并重新进入；`orders` 的动作启动计数不得再次增加，最终只产出一把铁镐；
- 工作站竞争：给两名 `PLANNED` 铁匠创建指向同一铁砧的订单；同一时刻最多一名进入 `ACTING`，另一名显示 `WORKSTATION_BUSY`；
- 终态清理：完成后 `reservations` 的互斥资源与生产原料预留均须显示 0 项，重复查看或重载不能再次消耗原料。
