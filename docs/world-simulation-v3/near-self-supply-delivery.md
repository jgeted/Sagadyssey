# 近处自养完整交付验收（2026-10-19）

本文件接续 `near-food-cycle-acceptance.md`。旧报告记录的是受控生长、锁定白天和预装燃料条件下的阶段性成果；当前交付补齐正式家庭来源登记、原料及燃料持续补给，使用默认生长和真实昼夜验证整条链路，并验证运行中的保存重启。

## 交付合同

允许一次性配置居民、职业、家庭、耕地、水源、照明、床、仓储、原版加工设施、工作区域与明确权限。此后，在已配置的近处合法资源充足时，生长、收获、留种、入库、原料运输、燃料运输、加工、家庭补给和实际进食持续衔接，不依靠测试催熟或日常手工塞入燃料与食物。

物资不足或出库受阻时，必须保留真实物品、未结运输义务及原因；条件恢复后由原机制继续。运行中保存重启后，由原人物继续原义务，不能复制物品、重复消费或用新人物替换原人物。

本合同不要求无人建造设施、无限矿产、通用食品配方、远方物理生产或全世界任意人口配置。正常供给与资源不足分别验收，资源枯竭不会被假装成无限自给。

## 实现范围及复用

运行时只调整两个文件：

- `SupplyBrainCommand`：增加家庭主体的来源和储备登记；明确区分知识登记、所有权声明、转移授权。个人储备命令的物品参数改用原版资源标识参数，修正原入口无法解析 `minecraft:potato` 的问题。
- `ProductionContainerIds`：首次发现已分配的私人/家庭储物时，使用其已确定的角色身份；继续保留现有物理登记及已存在权利上下文的优先级，不自动迁移或重写旧存档资产身份。

继续使用 SupplyFlowData 的知识和储备策略、NeedRequestData 的需求与回执、既有专职运输者、Fieldwork 的真实采集入库、RightsStateData/TransferService 的权限与转移，以及原版熔炉和漏斗。没有增加新运输资格、通用烹饪后端或加工槽位写入权限。

原料先进入普通仓库，再由精确土豆储备策略运到输入缓冲桶；副产物不会因一次收获而一起灌入熔炉。煤由实际近处采矿取得，经过独立燃料缓冲桶和原版侧向漏斗进入熔炉。普通仓储白名单保持不变。

### 正式管理入口

下列入口继承 `/saga supply` 的管理员权限要求，供一次性配置使用：

```text
/saga supply know-source <成员> <来源位置>
/saga supply household-source <成员> <已登记来源位置>
/saga supply household-source <拥有该来源的成员> <来源位置> allow-transfer
/saga supply household-source <成员> <未占用空桶位置> register-empty
/saga supply household-buffer <成员> workshop minecraft:potato 8 <输入缓冲桶位置>
/saga supply household-buffer <成员> workshop minecraft:coal 4 <燃料缓冲桶位置>
```

`household-source` 单独使用只增加家庭知识。`allow-transfer` 是明确的转移授权，不更改来源所有权；不能由另一个成员代授权私人资产，也拒绝容器内第三方资产主张。`register-empty` 明确登记尚未占用的空容器，不接管他人私人仓库、其他家庭已分配的粮仓或已有物品。新储备任务以家庭为主体，因此原家庭运输者可以依法领取，无须让农民或矿工冒充运输员。

## 已冻结的五项结果

| 必要任务 | 验收结果 |
| --- | --- |
| 正式家庭来源接入 | 通过实际命令分发器配置来源及缓冲，不在正常运行用例中直接写入知识或转移授权账本。正向入口及知识不授予处分权、禁止代授权、禁止接管其他家庭空仓、禁止代授权第三方资产的负向断言通过。 |
| 持续原料与燃料补给 | 熔炉、燃料桶和工人库存初始煤均为 0；煤全部来自近处真实矿石。原料和煤均经过真实入库、预留、取货、运输、交付及原版漏斗，不手动装填加工槽。 |
| 默认环境产消运行 | 随机刻速度为 3，开启昼夜循环，有真实床位；没有直接调用作物生长或设置成熟年龄。连续观察超过五个完整游戏日，三名原居民均反复进食，所有原料、配方转换、熟食及副产物守恒。 |
| 停产与恢复 | 实际耗尽燃料后观察停产，再开放预先存在的近处矿点，由原矿工、运输者恢复供给。满出库桶时不报告虚假交付，使用原转移服务将障碍物移入另一只箱后，运输及进食恢复。 |
| 运行中保存与恢复 | 在真实 CARRYING 状态保存，未暂停、替换人物或清空义务。独立 JVM 加载同一世界后，原人物身份和原运输路线保留并完成，之后继续加工、进食及守恒核对。 |

## 实测数量

最终正常运行 `normal-final.log`：默认生长、真实昼夜，经过 **120276 刻**，约五个完整游戏日。三人初始饥饿均为 120，初始家庭无熟食，农民随身有 16 个种薯，田中另有 12 株零龄土豆；矿工配有一把初始铁镐，工作区内有 21 块真实煤矿石。

- 田间回执净土豆变化：43。
- 所有物理节点生土豆：26；实际熔炉配方完成：33，故 `16 + 43 = 26 + 33`。
- 三名居民各完成至少三次进食，总计 9 次；剩余熟食 24，故 `33 = 24 + 9`。
- 实际采煤 21；剩余实物煤 13；燃烧消耗及空烧损耗由原版熔炉决定，未假定每个煤都必须产满 8 份食物。
- 保存时 `carrying=true`，保留真实正在运输的路线标识。

独立进程 `running-restart.log`：原三个人物与人物 ID 保留，原保存运输路线完成；1147 刻后加工总数从 33 增至 38，累计进食从 9 增至 10，新的物资守恒断言通过。正常休息状态核对通过。测试启动器恢复的是最终存档的游戏时间和昼夜时间，不把时钟倒回中途检查点。

燃料耗尽恢复 `fuel2.log`：初始只有一块可作业煤矿，其他两块已存在但在原工作边界外。确认实际燃料耗尽、队列中仍有真实土豆，并连续观察至少 800 刻没有继续烤制；随后仅扩大原矿工的合法作业范围，没有插入煤或食物。最终实际采煤 3、加工 15、进食 4，整个过程在 55660 刻完成并对账通过。

出库阻塞 `faults1.log` 中的单项成功记录：有真实熟食留在加工链中，家庭没有被报告为收到或消费这些食物。通过原转移服务搬走一组障碍物后，原链路恢复运输与进食；1728 个障碍物仍在原桶和转存箱中。该日志的整次运行曾因另一个燃料用例错误假设“一煤恰好八份产物”失败，因此这里只引用已通过的出库阻塞单项，不把整份日志宣称为全绿；燃料用例修正测量口径后单独通过。

首次接入试验保留了来源查找与实际入库身份不同、旧物品参数无法解析、个人任务无法由同户运输者领取等实际问题的记录。新测试的选择器前置条件和一次命令注册编译错误也保留原始日志，均不冒充业务失败复现。
