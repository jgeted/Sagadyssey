# Sagadyssey 战争系统生存验收

## 1. 进入测试场

在 Windows 安装 JDK 21，双击项目根目录的启动器。默认打开一个窗口，以 **CampaignB** 进入测试副本。你站在 `49.5 80 63.3`，快捷栏第一格是这片场地已绘制的原版地图。保存时 A、B、C 有 10、121、24 名战斗人员。 [Start-War-Acceptance.cmd](../../Start-War-Acceptance.cmd)

| 在项目根目录运行 | 用途 |
| --- | --- |
| `.\Start-War-Acceptance.cmd -Scenario Opening` | 小队场景，三方有 3、5、4 名战斗人员，适合从 NPC 招募开始验收 |
| `.\Start-War-Acceptance.cmd -Scenario Battle -Players ABC` | 三个普通生存账号进入同一场地，可验 A/C 联合计划和 B 的权限 |
| `.\Start-War-Acceptance.cmd -Scenario Skirmish -Players ABC` | 在一份新副本里预置 A/C 对 B 的战争关系，可直接验实际交战 |
| `.\Start-War-Acceptance.cmd -Resume <会话名>` | 接着玩一份测试副本。多人续测时带原来的 `-Players` |
| `.\Start-War-Acceptance.cmd -Check` | 检查本地 JDK 和测试种子存档 |
| `.\Start-War-Acceptance.cmd -ServerSmoke` | 后台检查开服、保存和关服 |
| `.\Start-War-Acceptance.cmd -OnlineBuild` | 直接让 Gradle 联网解析依赖，可和场景参数搭配 |

启动器用当前源码构建 Minecraft 1.21.11 测试环境。默认先使用 Gradle 缓存，首次缺少依赖时会自动尝试联网。三个随仓库提供的场景样本只含当前地图、原 NPC、军籍和 `CampaignA/B/C` 测试角色所需数据。每次常规启动在 `run/war-foreground/sessions/` 下解包新副本，启动窗口会打印路径和会话名。也可用 `-SeedWorld "D:\测试备份\world"` 指定已有场景存档。关闭所有测试客户端后，本地服务器会保存退出。各客户端和服务端使用同一份代码。

## 2. 三种入口

| 游戏里的动作 | 进入哪里 |
| --- | --- |
| 手持已绘制地图，潜行朝空中右键 | **军令地图**。查看己方兵团，点地预览，再确认发令。可进入**军籍簿**查编制、粮饷和联合计划 |
| 手持同一张地图，潜行右键近处 NPC | **军务面谈**。对已招募的人议定军役，对合资格的在役人员办理任免、委托和任务 |
| 选定现场兵团，拿地图右键实体旗帜 | **登记集结旗**。登记保存后，在有新近部队报告时吹山羊角下达现场集结，也可以当面委托合资格的助手 |

普通右键 NPC 可打开原人物界面，原招募、递交和装备都在这里。现场标记期间，屏幕下方会显示下一步。需要退出标记时，拿地图潜行朝空中右键。

## 3. 单窗口先验收这三件事

1. **把队伍调起来。** 打开军令地图，点选一支有人数和新近报告的兵团，再选「坚守」。点附近已绘制的开阔地，记录预览时 NPC 所在位置，然后按「确认发令」。看待送计数，等待 NPC 行进或进入坚守，核对部队报告。可再换一个目标试「行军」或「集结」。关闭一份未确认的预览，检查原军令是否继续。
2. **给同一个工兵任用，然后撤职。** 在军令地图选「军籍簿 → B → 核定编制与军职 → 核定战斗编制」，等保存后关闭。默认出生点附近 `49.5 80 61.5` 的工兵可以办理。持地图潜行右键他，选「任用军职 → 工程负责人 → 代理任用」，填写理由并确认。刷新查看在任，用「听取本人的建议」核对他实际掌握的报告，再用「撤销任命」观察恢复工兵服。脸型、肤色与实际装备可与任用前对照。
3. **委托 NPC 使用实物。** 与工程军役中的原工兵面谈，选「商议施工 → 构筑工事」，选本人背包里的材料。关闭页面后持地图右键起点、终点旁的实际方块面，空地上可点地面上表面，同一点选两次可做一格。看粒子预览，按「批准施工」，观察工兵到场、实体方块出现和材料扣除。材料可通过原递交界面给本人。

### 接着验后勤和组织

- **装备与转兵种**使用普通招募和装备流程。小队场景到 B 营地约 `18 80 55`，普通右键一名还没有服务约定的 NPC，在原界面选「提出服务约定」并支付实际签约礼。随后持地图潜行右键同一人，在「提出军役」选择军队、兵团、职责、军饷和天数，预览并递交本人决定。本人接受后，检查军服和兵团实际人数。退役完成、旧装具结清后，可经普通递交或装备界面换成原版长矛，再征召入军籍簿建立的长矛兵团。
- **编制门槛**用「核定编制与军职」看。随行队由领主直接指挥，可按需提拔兼任副手。队长须满足军队和本兵团规模。军务官、旗手、军需负责人和工程负责人各自需要相应编制和军役资格。
- **实体军库**在军籍簿选军队的「军库与粮饷 → 登记实体军库」，拿地图右键准备登记的真实箱子或木桶，再确认。旧库与账目可直接查阅。默认 B 库约在 `49 80 46`。到 `59.5 80 31` 附近找军务运输员，面谈选「商议运输 → 送给军士」，潜行右键本军收货人，选择库里实际物资、数量和趟数。观察原运输员领取、换上辎重外观、交付后恢复，并核对箱内数量和运单。
- **军务官、副手和旗手**用军令地图的「定为现场」选定兵团，地图右键实体旗帜后等登记。对有实际可用军职的 NPC 面谈，选「委托向原旗集结」。从任务页查办理和原军令回执。吹角也可直接集结。把旗移走，等山羊角冷却后再吹，查看军令有无新增。
- **工单与侦察**在工兵面谈中选挖掘、陷阱、地道或现场侦察，按现场提示逐点标记。通过工单检查暂停、继续或取消后，实物与已建方块的状态。「危险报告与排障」展示实际观察的情报，避让策略由领主选择。

## 4. 三方联机

在 `-Scenario Battle -Players ABC` 里切换三个窗口操作。每人都要持各自原地图。

1. A 打开「军籍簿 → 联合计划」，选「邀请盟友」并选 C。确认开令倒计时。C 收到后，在自己的军籍簿打开计划。B 的联合计划列表只显示 B 参与的计划。
2. A 和 C 分别用「添加己方军令」选自己的军队和兵团，再在实体地图投影上点出目标。让 A 选保留军报，C 选共享。A 在条款保存后签署，C 刷新并签署当前版本。查看回执中两个原指挥者的军令与各自的收令结果。
3. A 查「读共享军报」，观察 C 授权的记录。C 关闭计划后，再查共享报告和自己队伍的原军令。要验一个领主同时部署多个兵团，可用「本军多兵团计划」。
4. 用 `-Scenario Skirmish` 开一份交战副本，比较 A、C 在相近位置协同与一方晚到时的真实结果。保持两轮初始配置一样，每轮记录同一时间窗口内的到位人数、组织度、有效接敌、撤退和重整。近处面谈原队长，查机动、坚守、突击、撤收的个人履历和点数。

外交关系由项目的政治系统提供。交战副本从开服时就预置战争关系。付费租借和逐人确认后转军籍属于另行设计的功能。

## 5. 保存验收记录

在测试场退出游戏后，用会话名恢复副本。核对原军役、军职、粮饷、已收军令和工单。发现问题时记下角色、兵团、操作和预期现象，按 `F2` 留截图。截图和客户端日志位于会话的 A/B/C 子目录，服务端日志位于 `Server/logs/latest.log`，构建日志位于 `build.log`。

用 `-ServerSmoke` 可以先检查所选场景能否开服并保存。判断无命令交互是否通过时，请按第 3、4 节检查玩家界面、实际 NPC 动作和保存后的状态。
