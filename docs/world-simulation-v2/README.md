## 0. 结论

这次不应继续在旧 NPC 界面上追加按钮，也不应只把 NPC 物品栏扩成 36 格后保留旧交易逻辑。Sagadyssey v2 应把整个系统改造成：

**一个由独立人物、有限认知、真实财产、关系与制度共同驱动的世界。**

玩家不是后台管理员，NPC 也不是可购买的功能集合。后端保存精确事实；每个人只依据自己观察、听闻、推断和获准查阅的内容行动。UI 不是数据库窗口，而是当前玩家人物对世界的认识投影。

本设计正式作出以下决定：

1. NPC 与玩家采用相同的 36 格个人物品栏语义；不设 NPC 专用箭袋槽。弓、箭、食物、工具和战利品都是真实物品。
2. 运输货物仍与个人物品栏分开，但原因是保管责任、所有权和任务交接，不是 NPC 身体结构特殊。
3. “招募即归玩家所有、切换为玩家阵营”废止。改为雇佣、宣誓、委任、同行、服役等有范围和期限的关系。
4. 玩家不能默认查看 NPC 全部物品、精确属性、思想和交易表。服务端只下发该玩家有理由知道的内容。
5. 给予物品改为世界内的递交行为；普通赠礼不再要求打开双方物品栏。
6. 固定配方商店废止。交易只能转移双方真实控制且有权处分的财物，并且双方都愿意接受条件。
7. 经济系统以生产、消耗、储备、权利、运输和本地信息为基础；价格只是局部信号，不是全世界共享的真值。
8. 家庭、行会、领主关系、聚落政府、宗教组织和商号是有成员、规则、资产、职位、义务与制裁能力的制度，不只是标签。
9. 已加载区域采用细粒度模拟，远方采用守恒的事件级模拟；降低细节不能凭空创造或删除物资。

## 1. 设计目标

### 1.1 玩家应感受到什么

- 面前的是一个有生活来源、亲友、职责、私人物品和自身打算的人，而不是职业皮肤。
- 帮助、雇佣、赠礼、欠薪、盗窃和背叛都会留下可解释的后果。
- 一个价格贵或便宜，应能追溯到短缺、风险、运输、关系或制度，而不是随机倍率。
- 了解一个人需要接触、共同经历、他人介绍或文书权限；不会因为打开 UI 就突然全知。
- 命令是否被执行取决于授权、能力、信息、风险与承诺，而不是 `isOwned`。
- 世界即使不围绕玩家也会继续变化，但不会为了制造“活着的感觉”伪造无来源的资源。

### 1.2 本设计不追求什么

- 不追求逐分子或逐金币模拟。
- 不追求把历史社会复制成教科书；历史资料用于避免明显失真的抽象。
- 不把所有行为都做成复杂界面。高频动作应更短，只有谈判、审计和管理才展开深层 UI。
- 不要求每个 NPC 每 tick 进行完整决策。
- 不用隐藏随机数冒充人格；玩家应能从经历中理解一个人的大致行为倾向。

## 2. 十一条不可破坏的世界不变量

这些不变量优先于任何界面便利和内容数量。

1. **物质守恒**：每次物品变化都有来源、去向、数量、时间和原因。
2. **占有不等于所有**：拿着、使用、保管、收益和处分是不同权利。
3. **人物不等于实体**：人物记录跨越实体卸载、失踪、死亡与历史记载；实体只是其当前身体。
4. **行动基于认知**：人物使用自己的信念和信息决策，不读取全局真值。
5. **客户端最小披露**：隐藏信息不能先发给客户端再靠 UI 遮住。
6. **授权有来源**：命令、取物、交易、征用和查看账簿都必须能追溯到职位、契约、亲属授权或财产权。
7. **交易不造物**：任何成交都必须在提交时再次验证库存、权利、容量和报价版本。
8. **行动有成本**：移动、工作、谈判、运输、照料、学习和调查都消耗时间并可能失败。
9. **关系具有维度**：信任、亲近、尊重、恐惧、义务、怨恨、熟悉度和正当性不能压成一个好感值。
10. **历史可追溯**：重要状态变化产生领域事件；存档迁移有版本，不能静默改写意义。
11. **细节可降、因果不可降**：远方可以少算，但产量、消耗、损失和所有权结果必须与细粒度规则兼容。

## 3. 世界的基本对象

### 3.1 人物 Character

`Character` 是有连续历史的社会主体。玩家账号只是一个人物的当前控制者；NPC 实体也只是一个人物的当前身体。

人物包含：

- 稳定身份：人物 ID、姓名历史、出生与死亡、血缘来源；
- 身体状态：当前实体、伤势、能力、位置、装备；
- 心理倾向：性格、价值、长期目标、当前需要；
- 社会关系：家庭成员关系、私人关系、契约、成员资格、职位；
- 认知：自己相信的事实、来源、可信度和过期时间；
- 财产与债权：直接财产、共有份额、保管物、欠款和应收款；
- 历史：见证、承诺、功绩、罪责、迁徙与职业经历。

`socialClass`、`office` 和 `factionId` 不再是人物身上的单一终极字段：

- 出身阶层保留为历史背景；
- 地位是特定制度和情境下的承认；
- 职位是有任命者、管辖范围、权力和任期的记录；
- 归属允许同时存在，例如家庭成员、村民、行会学徒、教区信徒与领主附庸可以同时成立。

### 3.2 家庭 Household

家庭不是“所有成员共享一个箱子”的同义词，而是居住、生产、消费和照料的协作单位。成员可以包括亲属、仆役、学徒、寄居者与受抚养者。

家庭具有：

- 成员及其关系和职责；
- 住所与家庭设施；
- 家庭共有财产、个人财产和被委托保管的财产；
- 食物、燃料、照料、租金和债务等共同预算；
- 内部决策方式与代表人；
- 继承、分户、婚入、寄居和驱逐规则。

家庭成员身份本身不授予处分其他成员私人财产的权利。

家庭还是一个会变化的生命周期主体，而不是创建后不变的名单：成员会成年、离家服务、婚入、分户、寄居、继承或死亡；职业和继承规则会改变家庭的规模、劳动力、资产与照料压力。系统记录变化过程，不用“随机增减人口”直接得到结果。

### 3.3 制度 Institution

聚落是空间与人口共同体；管理聚落的议会、领主家政机构或神殿则是制度。两者必须分开。

制度记录包括：

- 类型与司法/服务范围；
- 成员资格与退出条件；
- 职位、任命关系和权限；
- 规则、习俗、禁令与处罚；
- 资产、仓库、账簿、税费与债务；
- 对其他制度的联盟、竞争、臣属和管辖冲突；
- 被不同群体承认的正当性。

建议的首批制度类型：

- 家庭与家政组织；
- 村社/城镇政府；
- 领主家政机构与附庸网络；
- 手工业行会；
- 商号或商队；
- 宗教组织；
- 军事单位。

### 3.4 财产 Asset 与容器 Container

世界中的可交易物不是菜单结果，而是某个地点、人物或容器中的真实资产。

资产分为：

- 物品批次：可拆分、合并的 ItemStack；
- 装备与工具：有耐久、品质和历史；
- 容器内容：箱柜、仓库、载具货舱；
- 不动产使用权：住宅、农田、作坊、摊位；
- 债权与义务：欠款、应付工资、交货承诺；
- 货币与票据：仍然是可持有、可丢失、可拒收的资产。

### 3.5 契约 Contract 与义务 Obligation

契约不是“把 NPC 控制权交给玩家”，而是相互承诺的集合。它至少定义：

- 当事人及代表资格；
- 服务内容与工作地点；
- 可下达的命令范围；
- 工资、口粮、装备、保护或分成；
- 开始、期限、休息、续约和解除；
- 违约、欠薪、伤亡与争议后果；
- 哪些财物只是配发、哪些成为私人财产。

口头承诺也可以成立，但更难证明；书面契约或见证人会提高证据强度。

### 3.6 主张 Claim、证据 Evidence 与标准 Standard

真实世界不仅存在事实，也存在人物和制度提出的主张。玩家说“这把锄头是我的”、商人说“这枚币足色”、行会说“此人无权营业”，都需要分开记录：

- `Claim`：谁对什么提出何种主张；
- `Evidence`：占有、收据、契约、见证、印记、账簿或习俗；
- `Standard`：谁维护重量、面额、品质和身份资格标准；
- `Judgment`：哪个机构在何种管辖范围内作出裁决；
- `Enforcement`：裁决是否有能力执行。

后台真相不等于人人承认的社会事实。伪造、误认、争议与腐败因此有可玩的结构，而不是随机对话分支。

## 4. 社会结构：从单一阶梯改为重叠关系网

现实社会中的一个人不会只由“贵族/平民”决定。v2 使用多轴身份：

| 轴 | 示例 | 主要影响 |
|---|---|---|
| 出身与法律状态 | 自由民、依附者、外来者 | 默认权利、迁徙和司法待遇 |
| 家庭位置 | 户主、配偶、子女、学徒、仆役 | 照料义务、住所、家庭代表权 |
| 生计与技艺 | 农夫、铁匠、商人、佣兵 | 能力、生产网络、市场声誉 |
| 制度成员资格 | 行会成员、教团成员、村民 | 服务、保护、排他资格、会费 |
| 职位 | 执事、队长、法官、仓管 | 特定范围内的命令和管理权 |
| 政治关系 | 臣属、盟友、受保护者 | 军事义务、征税、保护与代表 |
| 名誉 | 可靠、欠债、欺诈、英勇 | 他人对交易与合作的判断 |
| 私人关系 | 亲近、信任、畏惧、怨恨 | 帮助、披露信息、风险容忍度 |

同一身份在不同语境下权重不同。行会大师在作坊内有权威，不代表他能指挥守卫；贵族在敌对城市也未必有合法处分权。

### 4.1 关系模型

人物 A 对人物 B 的关系至少包含：

- `familiarity`：是否认识、了解多少；
- `trust`：相信其陈述和承诺的程度；
- `affection`：私人亲近；
- `respect`：对能力、地位或品格的认可；
- `fear`：预期其可能造成伤害；
- `obligation`：认为自己欠对方多少；
- `grievance`：尚未解决的伤害与不满；
- `legitimacy`：承认对方在特定语境下命令自己的正当程度。

关系是有方向的：A 信任 B，不代表 B 信任 A。关系改变必须由事件解释，例如及时付薪提高可靠性，救助增加感激与义务，强行征用增加恐惧和怨恨。

## 5. 财产权：不是一个 owner 字段

### 5.1 权利束

对一个资产分别记录以下能力：

- `POSSESS`：实际持有或保管；
- `ACCESS`：接近和查看；
- `USE`：使用但不消耗；
- `CONSUME`：消耗；
- `MANAGE`：决定用途和分配；
- `EXCLUDE`：排除他人使用；
- `TRANSFER`：赠与、出售或永久转让；
- `INCOME`：取得收益。

例子：雇主把弓交给护卫后，护卫拥有持有和使用权，但没有出售权；商队车夫保管货物但不是货主；家庭仓管可以分配口粮，却不能把共有储粮赠给朋友。

### 5.2 物品栏规则

NPC 个人物品栏与玩家一致：

- 36 格个人携带空间；
- 装备槽使用原版语义；
- 弓与箭占普通物品格，AI 按可达性选择弹药；
- 可设置整理偏好，但不创造专用隐藏容量；
- NPC 捡起物品只改变占有事实，是否取得所有权由事件与规则判断；
- 死亡掉落、搜身、借用和偷窃都保留原财产权声明，直到合法转让、放弃或裁决。

独立保留的容器只有具有不同社会语义的容器：

- 运输货舱：承运人保管、货主所有、订单预留；
- 家庭仓库：可能包含共有、个人和代管批次；
- 机构仓库：受职位权限和账簿约束；
- 商人库存：私人或商号资产，不能由交易表生成。

### 5.3 堆叠与所有权

相同物品只有在所有权、质押、预留订单和来源限制兼容时才能无损合并。工程上采用“容器默认权利 + 例外批次声明”：

- 普通私人背包中的物品默认继承背包持有人的私人所有权；
- 配发物、赃物、订单货物或共有财产带轻量 `assetClaimId`；
- 拆分堆叠时继承声明；
- 所有权真正转移后生成新声明或回归目标容器默认权利。

## 6. 认知系统：后台真相与人物所知严格分离

### 6.1 三层结构

1. **世界真相层**：服务器中的人物、资产、契约和事件实际状态。
2. **人物信念层**：某个人相信什么，可能模糊、过时或错误。
3. **界面投影层**：依据当前玩家人物的信念与权限生成可见内容。

客户端永远只接收第三层。开发者调试界面是明确的例外，并需要权限。

### 6.2 知识条目

一个知识条目至少包含：

- 主体、谓词和值或范围；
- 认知者；
- 来源：亲眼观察、对方陈述、第三方证词、文书、推断；
- 来源身份及可追溯链；
- 置信度；
- 获得时间、最后确认时间和过期规则；
- 是否可转述、是否受保密义务约束。

例如玩家看到的不是 `morale = 63`，而可能是“看起来尚有斗志（刚刚共同作战）”；不是 `inventory[17] = 24 wheat`，而是“你看见他背着一袋粮食”。只有获准盘点仓库或共同整理物品时，才显示精确数量。

### 6.3 信息来源与传播

- **观察**：外观、公开行为、明显伤势、手持/穿戴物。
- **交谈**：对方愿意透露的身份、需求和意图，可能撒谎或保留。
- **共同经历**：战斗、旅行、履约、救助形成高可信私人知识。
- **证词与流言**：受说话者可信度、传播距离和利益影响。
- **文书**：账簿、契约、告示和身份凭据；精确但可能伪造或过期。
- **职位权限**：仓管、户主、官员能看到职责范围内的记录。
- **推断**：从价格、行为、服饰和缺货状态推测，置信度较低。

### 6.4 精度与不确定性的显示规则

界面精度由“角色能否核对”决定，不以“沉浸感”作为模糊一切的借口：

- 玩家自己的背包、已展示的交易数量、自己签署的契约：显示精确值；
- 亲眼观察但无法测量的状态：显示可感知区间，例如“明显疲惫”；
- 他人陈述：显示内容、说话者和时间，不替玩家保证真实性；
- 推断和流言：显示方向、来源与新旧程度，不显示伪精确置信百分比；
- 专业鉴定：可以提高精度，并保留鉴定者、工具和标准；
- 信息彼此冲突时并列展示，不由 UI 偷偷选择“正确答案”。

## 7. NPC 决策：有界理性而不是全知最优化

人物不会遍历全世界寻找数学最优行动。每次决策流程为：

1. 从当前地点、记忆、日程、责任和接收到的消息生成少量候选行动；
2. 根据主观需要、性格、关系、义务、风险、机会成本和可行性评价；
3. 排除无权限、无信息或不可达的行动；
4. 采用带噪声的满意化选择，而非永远选最高分；
5. 形成短期承诺，避免每 tick 反复横跳；
6. 行动结果生成记忆、关系变化和世界事件。

核心需要保持克制：饥饿、休息、安全、照料、归属/承认以及履行重要义务。职业和制度不应再额外制造一套相互冲突的“需求条”。

NPC 可以做出错误选择，因为其消息错误、经验不足、情绪强烈或时间不足；但错误必须能由其已知信息解释。

## 8. 互动与 UI

### 8.1 不再存在“万能 NPC 管理窗口”

互动分为四层：

1. **观察层**：世界内外观、动作、称呼、公开标记；
2. **近身动作层**：交谈、递交、请求、帮助、出示、威胁、搜查；
3. **关系/谈判层**：交易、雇佣、借贷、任务、争议；
4. **记录层**：人物志、契约簿、账本和机构管理。

玩家只看到当前可做的动作。没有命令权时不显示“跟随/巡逻”；不知道对方是铁匠时不显示铁匠服务；没有搜查权时不显示完整物品栏入口。

### 8.2 近身交互布局

短按交互键执行当前首要动作；按住交互键打开小型情境动作盘：

```text
                 [交谈]
        [请求帮助]       [递出手中物]
    [出示物品/文书]       [提出交易]
          [同行/命令]*   [更多…]

* 只有存在相应授权时出现
```

动作盘不是后台菜单：每个选项对应世界中的动作、耗时和对方反应。

### 8.3 人物志，而非属性检查器

人物志保存“当前玩家人物知道什么”，并标注来源与新旧程度：

```text
┌ 人物：玛拉 ──────────────────────────────────────┐
│ 可确认身份             │ 关系与经历              │
│ 村里的铁匠学徒         │ 你曾帮她找回工具        │
│ 据本人说来自北边       │ 她对你比较信任          │
├───────────────────────┼────────────────────────┤
│ 近况                   │ 可采取的行动            │
│ 看起来疲惫             │ 交谈 / 递交 / 提议交易  │
│ 手臂似乎受了伤         │ 询问工作 / 查看契约*    │
├───────────────────────┴────────────────────────┤
│ 笔记：三天前见她收购木炭；消息可能已经过时。      │
└─────────────────────────────────────────────────┘
```

未知项目直接不出现，不显示一大片“？？？”诱导玩家把人物当收集进度。精确生命值、攻击、速度、人格分数、AI 效用和背包内容默认仅在调试模式出现。

### 8.4 查看物品

NPC 有与玩家相同的物品栏，但玩家是否能看取决于情境：

- 可直接看见：手持、穿戴和明显背负物；
- 对方主动展示：交易货物、准备交付的物品；
- 共同管理：合同明确授权的补给与装备；
- 合法搜查或医疗：限于授权目的；
- 偷看/偷窃：属于有风险的世界行动，而不是免费 UI 权限。

即使有查看权，也不自动有拿取或处分权。

### 8.5 UI 的双重职责

UI 同时服务两件事：保持世界一致性，以及让玩家清楚地作出决定。两者冲突时采用分层表达：

- 世界内动作与短反馈承担观察、递交、出示和接受/拒绝；
- 人物志保存来源、时间和关系经历；
- 谈判桌精确呈现双方已展示的资产和条款；
- 契约簿与账本处理需要核对的复杂内容；
- 管理员审计页单独显示真值、AI 分值和权限解析链。

因此不追求“百分之百无 HUD”。正式界面可以清晰，但不能让角色凭空获得知识。

## 9. 高效给予：世界内“递交”，不是开箱

### 9.1 高频流程

1. 玩家手持物品看向 NPC；
2. 选择“递出手中物”或使用可配置快捷键；
3. 默认递出 1 个，潜行操作递出当前整组；
4. 系统根据上下文推断意图并让玩家在必要时选择：赠礼、交付、借用、配发、付款或展示；
5. NPC 根据需要、关系、容量、风险和制度规则接受、拒绝或询问；
6. 接受后由服务器原子转移物品并记录事件。

普通低价值赠礼无需二次窗口。整组贵重物、权利不明确的物品、借用和配发需要一句简短确认，防止误操作。

### 9.2 不同意图产生不同后果

| 意图 | 所有权变化 | 典型后果 |
|---|---|---|
| 赠礼 Gift | 转移给接受者 | 感激、疑虑、义务或拒绝 |
| 交付 Delivery | 按订单转给委托方 | 履约、结算、减少欠交量 |
| 配发 Issue | 通常不转移 | 接受者获得使用/保管权 |
| 借用 Loan | 暂不转移 | 形成归还义务和期限 |
| 付款 Payment | 按债务转移 | 清偿工资、欠款或税费 |
| 展示 Show | 不转移 | 产生知识，不进入对方物品栏 |

### 9.3 批量补给

给一个人或队伍长期补给不应反复手递。玩家可以：

- 指定一个自己有权管理的容器为补给点；
- 建立物品类别、最低储备、领取上限和受益人；
- NPC 在需要、获准且能够到达时领取；
- 每次领取仍记录真实来源、数量和责任。

## 10. 交易系统

### 10.1 成交的必要条件

一笔交易只有同时满足以下条件才能提交：

- 双方身份和代表资格有效；
- 双方实际拥有或获准处分所承诺的资产；
- 资产未被其他订单、契约或债权预留；
- 双方当前仍愿意接受条件；
- 物品存在且数量、品质、耐久符合描述；
- 接收方有容量或指定交付地点；
- 报价版本未过期；
- 交易未被当前适用的制度规则禁止。

### 10.2 交易不是职业配方

NPC 能交易的内容来自：

- 自己愿意出售/交换的私人财产；
- 家庭授权其处置的剩余物资；
- 商号或机构委托销售的库存；
- 明确代理或寄售的货物。

NPC 想要的内容来自：

- 生存与家庭储备缺口；
- 当前生产计划的投入；
- 契约、债务或机构订单；
- 预计转售机会；
- 个人偏好、礼俗和关系义务。

职业只影响知识、需求和网络，不直接凭空提供商品。

### 10.3 谈判界面

```text
┌ 你与玛拉谈判 ─────────────── 地点：河桥集市 ───────┐
│ 你提出                         │ 她提出              │
│ [木炭 x12] [绿宝石 x3]        │ [修好的铁锄 x1]     │
│                                │                      │
├───────────────────────────────┼──────────────────────┤
│ 你可加入的财物                 │ 她愿意谈的财物       │
│ 仅列你有权处分的物品           │ 仅列已展示/获知库存  │
├───────────────────────────────┴──────────────────────┤
│ 她的回应：木炭有用，但数量还不够；也可两日后补交。  │
│ [修改提议] [接受] [提出赊欠/交货] [结束谈判]        │
└──────────────────────────────────────────────────────┘
```

界面不显示隐藏的“真实价值 = 127”。反馈通过人物语言、已知行情和可解释条件表达。专业商人或经过鉴定的账本可以提供更精确估价。

### 10.4 交易会话

交易使用稳定会话和提案 ID，不使用“第 3 个交易配方”这样的数组索引。状态为：

`OPEN → PROPOSED → COUNTERED/ACCEPTED → COMMITTED`，也可能进入 `EXPIRED/CANCELLED/FAILED`。

双方接受只代表同意；最终提交仍由服务器重新验证并一次性转移全部资产。任何一项失败则整笔回滚，不允许一方扣款、另一方未收货。

### 10.5 礼物、市场与交换不能混为一谈

- 赠礼重关系、礼俗和未来义务，不要求即时等价；
- 互惠交换允许延迟回报；
- 现货交易追求当场清算；
- 雇佣交换时间、劳动与报酬；
- 税、租、贡赋和征用依赖制度权力与正当性；
- 债务与赊购把履约风险带入未来；
- 偷窃和掠夺改变占有，不自动产生合法所有权。

### 10.6 信用、品质与争议

交易条款允许：现货、延期交货、赊欠、分期、担保、抵押和寄售。它们不共享一个抽象信用分：

- 信用是“债权人基于已有知识，是否相信该债务人在期限内履约”；
- 担保人、见证、文书、抵押和行会成员资格会改变风险与追偿方式；
- 欠款同时生成债权、债务、到期日、履约记忆和可能传播的声誉；
- 物品品质分为实际品质、卖方陈述、买方判断和鉴定结果；
- 市场机构可维护秤、币制、印记与纠纷程序，也可能偏袒、腐败或缺乏执行力。

第一版实现只做现货交换；数据结构从一开始允许未来义务，避免以后再次推翻交易模型。

## 11. 经济系统

### 11.1 经济主体

人物、家庭和制度都可以拥有资产、提出需求和承担义务。不能把整个聚落当作一个共享背包。

### 11.2 生产与消费

每个生产过程必须说明：

- 劳动者及其能力；
- 工作地点与工具；
- 输入物及其来源；
- 所需时间、季节与风险；
- 输出、副产品和损耗；
- 输出财产权根据何种规则归属。

消费同样从真实库存扣除。饥荒不是一个聚落计数器，而是家庭和机构无法取得足够食物的累积结果。

### 11.3 储备与需求

主体为物品类别维护目标储备区间，而非无限需求：

- 低于最低储备：强需求；
- 位于安全区间：弱需求；
- 高于目标上限：更愿意出售；
- 易腐、仓储不足、债务到期会降低保留意愿；
- 战争、寒冬、疾病和传闻会改变目标储备。

### 11.4 估值与价格

估值由主体根据以下信息形成：

- 当前需要和储备；
- 预期用途或转售机会；
- 已知本地成交与报价；
- 距离、运输能力、危险和损耗；
- 对交易对象的信任与信用风险；
- 制度税费、禁令、垄断和资格限制；
- 信息是否陈旧、样本是否稀少。

因此同一物品在不同人物、时间和地点可以有不同保留价。聚落“市场价”只是近期公开成交的统计区间，不是强制统一价。

### 11.5 货币

货币也是一种被接受的资产，而非无条件通用数字：

- v2 基线只使用 MC 已存在的绿宝石，以及直接物物交换；
- 不使用并不存在于游戏中的“银币”“金币”等占位货币；
- 只有未来确实加入了对应物品、取得来源和接受规则后，才可启用自定义实体币种；
- 接受度取决于当地习惯、发行者信誉和鉴别能力；
- 账簿信用只在认可该账簿和债务人的网络中有效；
- 系统不为找零或工资凭空生成货币。

### 11.6 商人的作用

商人通过信息、运输、储存、信用、鉴定和承担风险获利。其优势是网络，不是无限库存。商人破产、被劫或路线中断会真实影响供给。

### 11.7 信用与流动性

没有足够硬币不等于经济停止。双方可以在信任和追偿条件允许时使用：

- 延期付款或交货；
- 记账单位下的实物清偿；
- 由熟人、家庭或行会担保；
- 抵押工具、货物或未来产出；
- 多笔债权相互抵销。

但信用不是免费货币：它把支付问题转换成未来风险。战争、流言、歉收和连续违约会让放贷者缩短期限、要求担保或拒绝赊欠。

### 11.8 劳动不是单一工资公式

工作关系至少区分：家庭协作、按件任务、日工/季节工、长期住家服务、学徒、职位义务与被强制的劳役。报酬可以包含货币、食宿、训练、保护、工具使用和产出份额。

这些关系在自由程度、生活控制、解除方式和社会评价上不同。游戏不得把所有历史强制关系包装成自愿职业；人物对此可以服从、协商、逃离、抵抗或寻求其他权威保护。

## 12. 工作、命令与“招募”

### 12.1 服务关系替代所有权

旧字段：

```text
isOwned + ownerUUID + faction=player
```

新结构：

```text
ServiceRelationship
  principal
  agent
  basis          // 合同、宣誓、职位、亲属协作、临时同行
  scopes         // 护卫、运输、巡逻、生产、代表谈判……
  obligations    // 工资、口粮、保护、休息、装备……
  limits         // 地域、时间、风险、不可做事项
  start/end
  revocation and breach rules
```

人物原有家庭、家乡、身份、财产和关系不会因接受工作而消失。

### 12.2 命令的判定

系统依次判断：

1. 玩家人物是否对该事项拥有授权；
2. NPC 是否收到并理解命令；
3. 命令是否在契约/职位范围内；
4. 是否与更高义务、紧急需要或法律冲突；
5. NPC 是否有能力、工具、信息和路径；
6. 关系、风险与违约代价是否使其愿意执行；
7. 形成接受、协商、拒绝或暂缓结果。

因此“服从”不是恒定布尔值。一个可靠护卫会执行危险任务，但可能拒绝伤害家人或执行明显超出契约的掠夺命令。

## 13. 制度与政治

### 13.1 领主关系

领主权威不能简化为“拥有土地上的所有人”。它通常混合：保护、代表、司法、征收、军事义务和剥削。v2 将其拆成具体权利与义务，并允许不同人对其正当性有不同判断。

### 13.2 行会

行会同时可能：

- 提供训练、质量标准、互助和信誉；
- 管理学徒晋升与市场准入；
- 排斥外来竞争者、操纵供给或偏袒强势成员。

因此行会不是纯增益，也不是纯反派；其规则会产生受益者和受损者。

### 13.3 法律、习俗与冲突

行为结果不仅有“成功/失败”，还可能产生不同主张：

- 玩家认为自己依据契约有权取货；
- 家庭认为该货物是共有财产；
- 领主机构主张欠税扣押；
- 实际保管者拒绝承认其中一方。

系统记录主张、证据和执行能力，不强行假设世界总有唯一被所有人承认的法律答案。裁决、报复、妥协与战争由此产生。

### 13.4 共同资源与多中心治理

森林、牧场、水源、道路和磨坊等共同资源不能标记为“公共，因此无限免费”：

- 村社可以规定成员、季节、配额、维护劳动和违规补偿；
- 领主可能主张税费或司法权，但未必负责日常管理；
- 家庭拥有具体使用份额，外来者可能需要许可；
- 行会、宗教机构和地方政府可能对同一资源拥有不同范围的权利；
- 规则是否有效取决于沟通、信任、巡查、制裁和共同收益。

权利解析必须返回具体管辖依据，而不是沿所有权树寻找一个最终主人。

### 13.5 世界社会模板

“中世纪”不是一种统一制度。每个世界或剧本通过 `WorldSocialProfile` 声明其灵感范围和初始规则：

- 家庭形成与继承；
- 土地、共同资源和迁徙权；
- 劳动与学徒制度；
- 市场、币制、信用和度量衡；
- 宗教、领主、村社和行会的管辖关系；
- 性别、出身和外来身份在不同制度中的实际限制。

这些是世界初始条件，不是不可改变的自然法。战争、人口变化、改革、灾荒与玩家行动可以改变制度。

## 14. 时间、空间与远方模拟

为了在 Minecraft 世界中保持规模，采用动态细节层级：

| 层级 | 场景 | 模拟内容 |
|---|---|---|
| L0 实体级 | 玩家附近、战斗、交易现场 | 路径、动画、槽位、即时感知与动作 |
| L1 区域级 | 已加载但不受关注 | 降频决策、真实容器、日程与工作批次 |
| L2 聚落级 | 区块未加载 | 依据已登记资产和计划执行日/班次事件 |
| L3 世界级 | 遥远且长期无接触 | 人口、制度、路线和重大事件的稀疏推进 |

规则：

- L2/L3 不读取未加载方块实体，也不假装访问箱子；只使用离线前登记并预留的资产。
- 降级前生成快照：人物位置语义、在途订单、容器摘要、进行中的生产。
- 升级时进行对账：将抽象结果落实到人物、批次和容器；冲突进入待处理队列，不静默复制。
- 玩家制造的封锁、盗窃或破坏如果远方模型尚未知，只能在信息到达或区域重新加载后影响其决策。

## 15. 历史与可解释性

重要动作产生领域事件，例如：

- `ItemTransferred`
- `GiftAccepted`
- `ContractSigned`
- `WageMissed`
- `OrderDelivered`
- `PropertyClaimDisputed`
- `RumorShared`
- `OfficeGranted`
- `InstitutionSanctioned`
- `CharacterDied`

事件服务三个目的：

1. 让状态变化可审计和排错；
2. 为记忆、关系、传闻和编年史提供共同来源；
3. 让玩家能理解“为什么发生”，而不是看见无因果的数值跳变。

系统采用“当前快照 + 有界审计事件”，不要求完全事件溯源。普通重复事件可聚合；影响权利、契约、死亡和重大历史的事件长期保留。

## 16. 典型完整流程

### 16.1 给饥饿农夫一块面包

1. 玩家观察到农夫动作迟缓，只获得“似乎很饿”的知识。
2. 玩家手持面包执行“递出”。
3. 系统识别为默认赠礼；农夫判断食物安全、自己有需要、关系无明显敌意并接受。
4. 一块面包从玩家物品栏转到农夫物品栏，所有权转移。
5. 产生赠礼事件；农夫获得来源可靠的记忆，关系中的信任/义务小幅变化。
6. 农夫在合适时机食用；食物真实消失，饥饿下降。
7. 旁观者只在能看见或后来听闻时获得相应知识。

### 16.2 与铁匠换一把锄头

1. 铁匠确有一把可处分的成品锄头，并缺木炭。
2. 玩家通过交谈得知她愿意谈锄头与木炭；这成为有时间戳的知识。
3. 双方进入谈判，玩家提出 12 木炭与 3 枚绿宝石。
4. 铁匠依据库存、家庭需求、近期行情和对玩家信用评价，接受或反提议。
5. 提交时服务器锁定并复核双方资产、权利、数量与容量。
6. 资产一次性交换，记录成交；本地市场统计从该真实成交更新。

### 16.3 雇佣护卫

1. 玩家提出有期限的护卫合同，不购买人物。
2. 护卫根据危险、工资、口粮、声誉、家庭责任和替代机会决定。
3. 签约后玩家获得“路线内护卫与紧急防御”命令范围；护卫保持自己的身份和私人财产。
4. 配发弓只赋予使用/保管权；箭放在普通物品栏。
5. 欠薪形成真实债务、记忆和合同状态；连续违约可导致拒绝工作、离开、追债或传播坏名声。

## 17. 与现有设计的关系

### 17.1 保留并扩展

- 人物与实体分离的 `CharacterRecord` 思路；
- 家庭、私人储物与机构仓库分离；
- 有期限合同、实物工资与欠薪；
- NPC 记忆、关系、长期目标和带噪声决策；
- 真实仓储与物流订单；
- 聚落空间记录与世界编年史；
- “可感知、不可全控”的阵营原则。

### 17.2 被本设计取代

- `isOwned/ownerUUID` 作为人物关系核心；
- 招募时将 NPC 永久切换为玩家阵营；
- `PLAYER` 作为工作权威类型；
- 单一 `socialClass/office/faction` 表达完整身份；
- 9 格 NPC 背包、专用弓槽、专用箭槽；
- 向客户端发送完整精确属性再隐藏；
- 按职业注册固定交易配方；
- 扣玩家成本后直接生成交易结果；
- 所有关系压缩为单一强度或声望数值；
- 聚落总量可以替代真实主体和真实资产的设计。

旧文档仍可作为历史和内容素材，但发生冲突时，以本 v2 目录为准。

## 18. 成功标准

v2 不是以“有多少界面”验收，而以以下问题能否回答验收：

- 这件物品从哪里来、现在由谁持有、谁有权卖？
- 这个人为什么知道这件事，信息是否可能过时？
- 他为什么接受或拒绝命令？
- 这个价格为什么在此地此时成立？
- 欠薪、偷窃、赠礼或救助如何进入记忆和关系？
- 玩家离开后，生产与消费是否仍守恒？
- 旧存档是否能明确迁移，没有静默吞物或改变人物身份？
- 客户端是否无法通过抓包得到角色无权知道的秘密？

只有这些问题都有可追溯答案，世界才真正“真实”，而不只是显得复杂。

## 19. 可操作演示

[世界模拟 v2 交互演示](../../prototype/world-simulation-v2-demo/README.md)把以下纵向流程做成了可直接操作的静态原型：

`观察与交谈 → 获得带来源的知识 → 手递赠礼 → 真实库存谈判 → 原子交换 → 有限范围契约`

演示还提供“后台真相”设计审查抽屉，用于对比服务器精确状态和普通玩家实际可见的投影。该抽屉只属于原型与管理员工具，不能成为正式客户端协议的一部分。
