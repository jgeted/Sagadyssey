# 世界模拟 v2：测试者观察与后台真值面板

> 状态：设计基线，尚未实现统一面板  
> 目标：让获授权测试者在不改变世界、不污染人物认知的前提下，核对世界真值、人物信念、玩家投影及完整因果链  
> 关联文档：[总体设计](./README.md) · [技术架构](./02-technical-architecture.md) · [游戏内验收](./05-gameplay-validation.md)

## 0. 结论

测试者必须能够查看后台状态，但后台状态不能混进普通玩家界面。

正式方案定为 **验收观察模式（Verifier Mode）**：

- 只有服务器明确授权的测试者能启用；
- 查看行为完全只读，不产生知识、关系、历史或 AI 刺激；
- 同一事实并列显示“世界真值—指定人物信念—指定玩家投影”；
- 支持实时观察、固定 tick 快照、前后差异、守恒检查和因果时间线；
- 真值使用独立的管理员网络载荷，普通客户端永远不会提前收到；
- 退出、断线或失去权限后立即撤销真值载荷；
- 面板持续显示“后台真值 · 测试模式”水印，避免截图与普通玩家 UI 混淆。

它不是作弊玩法、人物能力或可解锁技能，也不会成为正式游戏获取情报的途径。

## 1. 当前已有能力

项目已经存在若干只读或诊断命令，但它们彼此分散：

| 当前命令 | 已能看到 | 主要缺口 |
| --- | --- | --- |
| `/saga scenario observe` | 固定场景档位、仓库实体库存、NPC 背包、货舱、工作状态和未完成订单 | 只覆盖附近固定场景；没有知识/投影/权利对照；仅管理员可用 |
| `/saga npc inspect` | 目标 NPC 的工作、需求、日程、性格、关系、记忆、合同、仓库和运输状态 | 聊天信息很长；没有投影对照；仅管理员可用 |
| `/saga assets audit [limit]` | 权利容器、例外声明和最近转移审计 | 只显示摘要，不显示容器级守恒差异 |
| `/saga service audit [limit]` | 服务关系和授权判定 | 不能从一次玩家操作直接跳到对应判定链 |
| `/saga knowledge audit <knower> <subject>` | 指定认知者对主体的信念、来源、置信度及部分管理员真值 | 需要手输 UUID；没有展示普通玩家最终收到的投影 |
| `/saga audit` | 角色、政治、物流、家庭等悬空引用 | 是一致性巡检，不是单次测试的前后差异 |
| `/saga economy` | 附近聚落人口、供给和缺粮天数 | 是聚合结果，不能解释每批粮食和每次价格变化 |

因此，测试者现在已经能做零散排查，但还不能高效回答：

1. NPC 为什么做出这次决定？
2. 它使用的事实是否真的在自己的认知中？
3. 玩家客户端最终收到了哪些字段？
4. 这批物品从哪个容器来到哪个容器？
5. 一次交易、护送或战斗到底影响了哪些系统？
6. 重启前后是状态合理变化，还是数据丢失/重复？

## 2. 权限与安全边界

### 2.1 谁能使用

首版只允许满足以下条件的主体启用：

- 命令源拥有 Minecraft 权限等级 2；
- 服务端配置允许验收观察模式；
- 玩家主动执行启用命令；
- 专用服务器记录启用者、开始时间和退出时间。

后续如需交给非 OP 测试人员，应新增独立权限节点，而不是把所有测试者都提升为服务器管理员。

### 2.2 会话规则

- 权限按玩家会话保存，不写入人物档案；
- 重新登录后默认关闭；
- 切换服务器后不能沿用；
- OP 权限被撤销时立即关闭；
- 面板关闭后服务端停止发送真值增量；
- 多人服务器上只向启用者发送，不向附近玩家广播；
- 测试者查看某人物，不会让该人物或玩家人物获得任何新知识；
- 查看行为不触发注视、交谈、敌意、犯罪、关系或事件。

### 2.3 已完成的基础权限隔离

以下含有明显后台信息的入口已经统一要求管理员权限等级 2：

- `/saga scenario observe`；
- `/saga npc inspect`；
- `/saga audit` 的完整世界一致性输出。

普通玩家需要的公开信息应通过知识投影、人物志、公开账簿或其实际管理权限提供，不能依赖这些诊断命令。

## 3. 当前命令与后续面板入口

第一版会话内快照命令已经可用，并全部要求管理员权限等级 2：

```text
/saga verifier list
/saga verifier snapshot <name>
/saga verifier show <snapshot_name>
/saga verifier diff <snapshot_name>
/saga verifier conservation <snapshot_name>
/saga verifier drop <snapshot_name>
```

- `snapshot before`：在当前服务端 tick 捕获不可变的后台摘要；同名快照会明确替换；
- `list`：查看本次服务器会话中的快照；
- `show`：查看场景、容器、领域计数和物品总量摘要；
- `diff`：把当前状态与快照比较，显示物品、领域记录和容器修订变化；
- `conservation`：集中显示物品指纹总量净变化和覆盖缺口；
- `drop`：只删除内存中的会话快照，不修改世界和存档。

第一版最多保留 16 个快照，服务器重启后自动清空。它覆盖已加载 NPC 的个人背包、
装备与运输货舱、在线玩家背包、已加载的登记仓库、家庭共享箱、NPC 私人箱和地面
掉落物。未加载或损坏的容器不会被强制加载，而是明确列为覆盖警告。

图形面板阶段继续沿用同一 `/saga verifier` 根命令，拟议增加：

```text
/saga verifier on
/saga verifier off
/saga verifier focus looked
/saga verifier focus scenario
/saga verifier observer self
/saga verifier observer <character_uuid>
/saga verifier timeline [ticks]
/saga verifier export <snapshot_name>
```

说明：

- `on/off`：打开或关闭测试者面板；
- `focus looked`：以准星所指人物、实体或容器为焦点；
- `focus scenario`：显示最近验收场的全局摘要；
- `observer`：切换要模拟的认知者/观察者，不改变当前玩家人物；
- `timeline`：查看近期因果事件；
- `export`：把快照、差异和违规项输出为本地测试报告。

命令只负责选择上下文和无界面环境下的回退。主要使用方式应是可搜索、可分页的游戏内面板，而不是在聊天栏打印几百行文本。

## 4. 面板布局

### 4.1 常驻顶栏

顶栏始终显示：

- 红色文字与图标：`后台真值 · 测试模式`；
- 当前世界、维度、游戏 tick 和现实时间；
- 最近场景、场景修订和测试档；
- 当前焦点主体；
- 当前模拟观察者；
- 实时/快照/差异模式；
- 违规、警告和陈旧信息数量。

真值面板打开时游戏不暂停。默认每秒刷新一次摘要；高频战斗事件通过增量时间线追加，避免每 tick 重发完整世界状态。

### 4.2 三栏事实对照

中心区域使用固定三栏，而不是把真值混在普通人物志里：

| 世界真值 | 人物信念 | 玩家投影 |
| --- | --- | --- |
| 服务端精确事实、版本和更新时间 | 该认知者相信什么、来源、时间、冲突与披露限制 | 服务端实际准备下发给该观察者的字段与表述 |
| 例如：商队货箱有面包 24 | 例如：玩家听商人说“还有一批粮”，三分钟前获得 | 例如：人物页显示“她似乎仍有粮食可谈” |
| 管理员可见 | 角色级状态 | 普通客户端真实可见边界 |

每一行额外标记：

- `一致`：投影与当前信念规则相符；
- `未知`：人物没有此知识，投影也未泄露；
- `陈旧`：信念有时间标记，投影正确降级；
- `争议`：多个独立来源冲突；
- `越权披露`：投影出现信念或权限中不存在的字段；
- `全知决策`：AI 使用了世界真值，但其信念中没有该事实；
- `格式伪精确`：投影把模糊认知显示成未经授权的精确数字。

颜色只作辅助，必须同时显示文字和图标。

### 4.3 快速焦点

面板打开时，准星指向对象应提供只读快捷焦点：

- NPC/玩家：人物、身体、社会关系、知识和当前决策；
- 箱子/木桶/货舱：实体库存、权利、预留、修订和最近转移；
- 农田/工作站：生产批次、投入、进度、工具和预期输出；
- 掉落物：来源事件、所有权声明和可拾取主体；
- 投射物：来源人物、弹药消耗和交战事件；
- 无对象时：显示最近验收场全局摘要。

## 5. 功能页

### 5.1 总览

显示当前场景是否处于可解释、可守恒状态：

- 主体、容器、交易、订单、事件数量；
- 已加载/未加载人物身体；
- 当前档位及与夹具清单的差异；
- 物品守恒状态；
- 悬空引用、过期预留和重复事件；
- 最近一次保存、加载和对账；
- 最严重的五个违规项。

### 5.2 人物与社会

对焦点人物显示：

- 稳定人物 ID 与当前身体实体 ID；
- 家庭及角色；
- 制度成员资格、职位和任期；
- 服务关系、合同、授权范围和到期时间；
- 私人关系的各维度与最近变化原因；
- 当前需要、目标、日程、候选行动和最终选择；
- 每个可执行命令的授权解析链。

必须区分“身份事实”“别人是否知道该身份”和“玩家界面是否显示该身份”。

### 5.3 资产与权利

对每个容器和物品批次显示：

- 物品 ID、组件指纹、数量和槽位；
- 当前实际持有者；
- 默认所有者和例外声明；
- `ACCESS/USE/CONSUME/MANAGE/TRANSFER` 等权利；
- 交易、消费或运输预留；
- 容器修订号；
- 最近转移 ID、意图、合法性和失败原因；
- 从场景开始至当前的总量变化及合法来源。

一键切换“按物品汇总”和“按容器展开”，方便检查面包总量和某个货箱的具体状态。

### 5.4 知识与投影

提供两种比较：

1. `认知者 → 主体`：某个人对另一个人物、容器、市场或事件知道什么；
2. `观察者 → 界面`：该玩家此刻实际会收到哪些字段、动作和描述。

每条知识显示：

- 主体、谓词和值/范围；
- 来源种类与来源人物/文书/事件；
- 首次获得、最后确认和过期时间；
- 置信度、冲突来源和是否可转述；
- 披露规则命中过程；
- 最终投影文本或被隐藏的原因。

测试者可以切换观察者，但不能通过切换观察者向任何人物写入知识。

### 5.5 经济、交易与运输

显示：

- 本地市场的最近成交、成交量权重、陈旧度和聚落边界；
- 商人访问过的市场、记忆时间与远地净机会；
- 报价拆解：物品估值、库存压力、每件运输成本、风险、关系调整；
- 当前交易会话、提案修订、反提议、预留和到期；
- 运输订单起点、终点、请求量、已取货、在途和已交付；
- 实体货物当前所在容器/人物；
- 失败运输为什么没有被错误记为到货。

价格拆解只属于真值面板。普通玩家界面应使用其能理解且有来源的理由，例如“这批货走了危险的远路”，而不是显示内部权重公式。

### 5.6 安全与战斗

显示：

- 安全事件类型、状态和状态变化历史；
- 报告、证词、物品转移、伤势等证据；
- 调查与派遣所依据的机构、职位和权限；
- 战斗双方、成员、交战规则和已发现目标；
- 每个人物实际知道的敌人位置与最后所见时间；
- 箭矢来源、消耗、命中/遗失；
- 伤势、士气变化、撤退、投降、逮捕和救援；
- 货损如何写回商队库存与后续市场供给。

若守卫攻击了其认知中不存在的目标，或没有授权便执行强制行动，面板直接标红并链接到相关决策事件。

### 5.7 因果时间线

时间线不只列日志字符串，而是连接事件：

```text
农田低产
  → 家庭储备下降
  → 农民形成“口粮紧张”认知
  → 玩家通过交谈获得陈述
  → 商队带入真实粮食
  → 高运输成本形成反提议
  → 玩家接受护送
  → 道路袭击造成箭矢与货物损失
  → 实际到货减少
  → 公共粮仓与本地市场更新
```

每个节点应能跳转到：

- 事件 ID 和 tick；
- 触发主体；
- 读取了哪些信念/权限；
- 改变了哪些状态；
- 对应的物品转移或战斗记录；
- 哪些人物因此获得了新知识。

## 6. 快照、差异与导出

### 6.1 原子快照

快照在服务端 tick 边界生成，至少记录：

- 世界和场景标识、档位、修订、游戏时间；
- 相关人物、家庭、制度与关系；
- 容器、资产声明、预留和修订；
- 知识条目和指定观察者投影；
- 市场、交易、订单、事件、伤势和战斗；
- 每类物品总量及其合法增减来源；
- 当前启用的 v2 特性和数据版本。

快照必须不可变。生成快照本身不保存世界、不推进时间、不加载远方区块，也不修改任何 `SavedData`。

### 6.2 前后差异

`diff` 默认只显示变化：

- 新增、移除和数量变化；
- 所有权、占有、预留和修订变化；
- 新知识、重新确认、过期和冲突；
- 新交易、转移、订单和安全/战斗事件；
- 关系和制度状态变化；
- 守恒差异与无法解释的状态跳变。

所有差异必须同时显示“之前—之后—原因事件”。没有原因事件的物质、权利或重要社会状态变化直接视为违规。

### 6.3 报告导出

导出包含两种文件：

- JSON：完整机器可读快照、差异、ID 和断言；
- Markdown：测试者可读摘要、失败项和关键因果链。

建议保存到服务端专用测试目录：

```text
run/sagadyssey-verifier/<world-id>/<run-id>/
```

文件名只接受安全短标签，服务端生成实际路径，禁止客户端提交任意文件路径。报告默认不包含聊天内容、账号令牌或与测试无关的玩家隐私数据。

## 7. 单人测试者工作流

用户自己同时担任玩家和测试者时，建议分成两个阶段，避免提前看答案：

### 7.1 盲测阶段

1. 用 OP 身份生成并重置目标档位；
2. 在服务端控制台或面板中创建 `before` 快照；
3. 执行 `/saga verifier off`；
4. 清理聊天提示，按普通玩家方式进入场景；
5. 不使用 `observe/inspect/audit`，完成探索和行动；
6. 先写下自己对原因、来源和后果的判断。

### 7.2 核对阶段

1. 执行 `/saga verifier on`；
2. 查看场景总览和守恒状态；
3. 选择关键 NPC，比较真值、信念和玩家投影；
4. 对 `before` 运行差异；
5. 沿因果时间线核对交易、运输或战斗；
6. 保存 `after` 快照并导出报告；
7. 重启服务器后再次差异，检查持久化与重复结算。

盲测时的玩家判断和核对后的后台解释都应保留。只有两者的差异，才能说明 UI 是过度泄露、表达不足，还是模型本身错误。

## 8. 双人/多人测试工作流

推荐使用一名普通测试玩家和一名独立观察员：

- 普通玩家完全没有 OP 或真值权限；
- 观察员保持远离场景或使用观察者模式，不参与互动；
- 观察员负责快照、时间线和异常记录；
- 服务端分别记录普通玩家收到的投影和观察员收到的真值；
- 测试结束前观察员不向玩家解释答案；
- 多名普通玩家同时测试时，分别保存每个观察者的投影，检查是否错误共享知识。

## 9. 网络与性能要求

### 9.1 独立载荷

- 真值使用独立的管理员载荷和处理器；
- 服务端在发送每个载荷前重新检查权限和会话；
- 普通 `NpcViewSnapshot` 不因面板存在而增加隐藏字段；
- 客户端缓存按服务器、世界、会话和观察者隔离；
- 关闭模式时清空客户端真值缓存；
- 不允许客户端仅靠猜 UUID 拉取任意世界对象。

### 9.2 负载控制

- 总览最多每秒完整刷新一次；
- 高频事件使用有界增量队列；
- 大列表分页、搜索并设硬上限；
- 默认只订阅当前场景或焦点主体；
- 远方未加载实体不为调试被强制加载；
- 导出和守恒扫描提供进度，但不异步修改世界；
- 面板本身的网络和 CPU 开销进入性能统计。

## 10. 观察模式自身的测试

### 10.1 权限测试

- 普通玩家不能看到命令建议、打开面板或请求真值载荷；
- OP 开启后仅自己收到；
- 撤权、断线和关闭后不再收到，客户端缓存清空；
- 伪造焦点 UUID、观察者 UUID 和旧快照 ID 均被服务端拒绝；
- `scenario observe`、`npc inspect` 和完整 `audit` 不再向普通玩家泄露。

### 10.2 只读测试

同一固定快照前后，仅执行查看、切页、搜索、切换观察者和导出：

- 世界 `SavedData` 不变；
- 人物知识和关系不变；
- AI 候选与行为不因被查看而变化；
- 容器修订号和库存不变；
- 不产生历史事件；
- 不触发区块加载。

### 10.3 对照正确性测试

- 构造真值已变、人物仍持有旧信念的情况，面板显示“陈旧”而非自动同步；
- 构造两个冲突来源，面板并列显示而不替角色选择；
- 构造没有知识的观察者，投影为空且状态为“未知”；
- 构造越权载荷，自动断言必须失败并指出字段路径；
- 对同一 tick 的命令文本、面板和导出 JSON，关键 ID 与数量一致。

## 11. 实施顺序

| 优先级 | 工作 | 完成条件 |
| --- | --- | --- |
| P0（已完成） | 给现有后台诊断加权限，明确普通信息与管理员真值 | 普通玩家无法调用真值入口 |
| P1（已完成） | 建立统一只读快照 DTO、守恒摘要和文本回退命令 | 能生成 `before/after` 并解释差异 |
| P2 | 实现三栏真值/信念/投影面板 | 任一 NPC 可按观察者进行对照 |
| P3 | 接入资产、市场、交易、运输、安全和战斗页 | 一次纵向场景能沿 ID 追踪完整因果 |
| P4 | 实现事件时间线与 JSON/Markdown 导出 | BUG 报告可复现、可比较 |
| P5 | 增加多人隔离、性能和恶意包测试 | 不泄露、不改变世界、负载可控 |

P0/P1 已可支持第一轮文字诊断；完整可视化面板可以与场景后续档位并行推进。

## 12. 完成标准

验收观察模式只有同时满足以下条件才算完成：

- 测试者可以看到精确后台状态和可追踪 ID；
- 能把同一事实的真值、信念和玩家投影并列比较；
- 能创建前后快照并解释每项重要变化；
- 能检查物品、权利、预留和事件的守恒；
- 能沿时间线追踪经济、社会和战斗的跨系统后果；
- 查看与导出不修改任何正式世界状态；
- 普通玩家无法调用、请求或缓存真值；
- 关闭和断线后真值访问立即失效；
- 面板性能不会显著干扰被测 AI 和服务器 tick；
- 导出报告足以让另一名开发者重现同一问题。
