# 世界模拟 v2：实施路线

## 1. 总体策略

这是一次世界模型重构，不适合“同时把全部系统改完”。采用纵向切片：每个阶段都交付一个可玩的完整因果链，再扩大覆盖面。

实现顺序不能从 UI 开始。正确依赖为：

```text
人物身份
   ↓
权利与真实资产 → 原子转移
   ↓               ↓
服务关系       递交与交易
   ↓               ↓
认知与投影 → NPC 决策/UI
   ↓
生产、市场、制度与远方模拟
```

## 2. 开工前基线

### 2.1 冻结与保护

- 把当前最后一个可运行 v1.x 状态建立 `v1.9-legacy` 标签或等价备份点；
- 记录当前脏工作树中哪些修改属于既有工作，禁止通过 reset 覆盖；
- 复制三个代表性旧世界作为迁移夹具；
- 保存物品清单、人物身份、合同、家庭、仓库和世界历史摘要；
- 新功能停止向 `NpcBase`、`NpcStatsPayload` 和固定交易表继续堆叠。

### 2.2 当前已知风险

- `NpcBase` 职责过多，任何直接大拆都可能影响战斗、动画和存档；
- 目前常规 `test` 没有测试源，现有社会验证偏源码字符串检查；
- 旧交易会造物，不能与新经济并行而不破坏守恒；
- 旧客户端已接收完整 NPC 状态，必须尽早封堵信息边界；
- 多个文档处于不同设计年代，v2 目录需成为冲突时的唯一基线。

## 3. 阶段 0：可测基座

目标：让后续重构有可靠护栏，不改变玩家玩法。

交付：

- 建立真实 JUnit/游戏测试目录和基础夹具；
- 加入物品总量、人物唯一性、容器修订号和网络包边界断言；
- 为现有 NPC 库存、交易、招募、合同与世界加载写特征测试；
- 增加数据版本框架和 dry-run 迁移报告；
- 增加 v2 feature flags，允许按世界关闭未完成功能。

验收门：

- 构建和新测试可重复通过；
- 三个旧世界可加载并生成一致基线报告；
- 没有修改正式存档语义。

## 4. 阶段 1：人物 ID 与 36 格物品栏

目标：先解决“人物是谁”和“真实物品放在哪里”。

交付：

- 建立稳定 `CharacterId ↔ BodyRef` 绑定；
- 把 NPC 个人物品栏迁移为 36 格；
- 取消弓槽、箭槽，改造战斗 AI 查找和消耗弹药；
- 运输货舱改为外部注册容器，不并入私人背包；
- 实现旧 9 格 + 弓箭槽迁移和异常保管箱；
- 增加迁移前后物品指纹核对。

暂不做：物权细分、完整新 UI、动态价格。

验收门：

- NPC 与玩家对相同物品遵守相同堆叠/槽位规则；
- 射箭真实消耗普通背包中的箭；
- 运输订单货物不会被误当私人补给；
- 旧世界迁移无吞物、复制或掉落。

## 5. 阶段 2：权利束与统一转移

目标：让每件重要资产的移动都有权限与原因。

交付：

- `ContainerContext`、`AssetClaim`、`RightGrant`；
- `RightsService` 及结构化判定依据；
- `TransferService`、幂等 ID、修订号、锁和回滚；
- 将工资、仓库领取、物流交付改走统一转移；
- 配发、赠礼、交付、付款、借用六种基础意图；
- 管理员资产审计命令。

验收门：

- 失败转移零副作用；
- 偷窃只改变占有，原所有权声明仍在；
- 雇主配发武器不能被护卫合法出售；
- 两名玩家竞争最后一件物品不会复制。

## 6. 阶段 3：服务关系替代所有权

目标：移除“NPC 属于玩家”的规则来源。

交付：

- `ServiceRelationship`、授权范围、双方义务和违约；
- 现有雇佣合同迁移；
- `ownerUUID/isOwned/PLAYER authority` 转兼容读模型；
- 命令可用性由授权动态生成；
- NPC 保留原家庭、制度成员资格和私人财产；
- 欠薪、越权命令、解约和恢复原工作流程。

验收门：

- 玩家不能因雇佣关系查看或拿取 NPC 全部私物；
- 合同外命令可协商或拒绝；
- 解约不改变人物身份或吞掉配发/私人财产；
- 旧存档的跟随、等待、巡逻能力有明确兼容关系。

## 7. 阶段 4：认知与面向观察者的 UI

目标：服务端真相不再直接等于玩家界面。

交付：

- `BeliefRecord`、来源、置信度、时效和传播；
- 观察、自报、证词、文书四种首批知识渠道；
- `ProjectionService` 与 `NpcViewSnapshot`；
- 情境动作盘与人物志最小版本；
- 精确属性和完整交易列表从普通载荷移除；
- 管理员真值/信念对照工具。

验收门：

- 陌生玩家、亲属、合同方、仓管看到不同且正确的投影；
- 抓取普通数据包不能得到隐藏库存、性格分数或 AI 决策值；
- 陈旧信息在 UI 中被标记或降级；
- 未知动作不会仅以灰色按钮泄露其存在。

## 8. 阶段 5：世界内递交

目标：完成用户最关注的高频给予流程。

交付：

- 手持物快捷递交与动作盘入口；
- 单个/整组数量规则；
- 接受、拒绝、询问意图状态机；
- 赠礼、付款、交付、配发、借用和展示；
- 容量、危险物、赃物、制度禁令判定；
- 事件、知识、关系和义务后果；
- 批量补给点与领取政策的最小版本。

验收门：

- 普通送食物不打开物品栏或大窗口；
- NPC 可因合理原因拒绝；
- 每种意图产生正确所有权结果；
- 误操作保护不妨碍高频小额递交。

## 9. 阶段 6：真实库存交易

目标：废除固定配方造物。

交付：

- `TradeIntent`、`TradeSession`、`TradeProposal`；
- 双栏谈判 UI 和自然语言反馈；
- NPC 只展示愿意处分且观察者有资格知道的资产；
- 真实库存预留、原子交换、过期和反提议；
- 现货物物交换及一种实体支付物；
- 旧 `NpcTradePacket/NpcTradeRegistry` 停用。

验收门：

- 成交前后物品守恒；
- 商人卖空后不能继续出售；
- NPC 需求变化会改变愿意接受的物品；
- 报价期间库存变化能安全失败并提示重谈；
- 多人并发购买同一件资产安全。

## 10. 阶段 7：家庭经济与生产

目标：让需求、生产和消费形成最小闭环。

交付：

- 家庭成员职责、个人/共有/代管财产；
- 家庭成立、寄居、离家、分户、继承的最小生命周期；
- 食物、燃料、工具三类储备目标；
- 农业或铁匠中的一条完整生产链；
- 输入预留、劳动进度、工具损耗和输出归属；
- 家庭消费与短缺后果；
- 工资、口粮与简单债务清算。

建议首条链：

```text
种子 + 土地使用权 + 工具 + 劳动 + 季节
→ 作物
→ 家庭留种 / 口粮 / 地租或税 / 可交易剩余
```

验收门：

- 聚落统计完全由人物/家庭/机构真实过程汇总；
- 缺粮能够追溯到生产、损失、分配或运输问题；
- 家庭成员离开会影响劳动与消费，而不是只改人口数；
- 同一物品不会同时被生产、消费和交易预留。

## 11. 阶段 8：本地市场、商人和信用

目标：让价格成为局部经济结果。

交付：

- 近期公开成交统计和陈旧度；
- 主体保留价、需求曲线和库存压力；
- 运输成本、危险、损耗和关系风险；
- 商人跨地观察与套利；
- 赊购、到期债务和信用记录；
- 担保、抵押和部分清偿的领域结构；
- 市场秤、品质印记和一种鉴定服务；
- 本阶段仍只使用绿宝石和物物交换；自定义币种不在 v2 实施范围内，若未来真的加入对应物品再单独设计。

验收门：

- 不同聚落价格差能由供需、距离或制度解释；
- 消息尚未传播时，远方 NPC 不会瞬间知道价格变化；
- 商人利润来自真实买入、运输和卖出；
- 商人被劫会减少库存并影响后续供给。
- 信用判断因交易对象和债务类型而异，不退化为全局分数。

## 12. 阶段 9：制度、职位与社会冲突

目标：把社会关系提升为能够行动的组织。

交付顺序：

1. 聚落政府或领主家政机构；
2. 一个手工业行会；
3. 税/租、职位权限和账簿；
4. 村社共同资源的成员、配额、维护与制裁；
5. 资格、质量标准、证据、裁决、保护与争议；
6. 制度间联盟、臣属与管辖冲突。

验收门：

- 权力来自职位/规则而非 faction 枚举；
- 制度有真实资产和支付能力；
- 行会同时能提供服务和施加排他规则；
- 违法、违约和不正当不被压成同一个声望扣分。
- 同一森林或水源可存在村社使用权、领主税权和家庭份额，而不寻找单一最高 owner。

## 13. 阶段 10：有限指挥、战斗与战后结算

目标：让战斗成为合同、信息、补给和社会后果的高压检验，而不是所有者对单位的直接控制。

交付顺序：

1. 用 `OrderIntent + AuthorityEvidence` 替换基于 owner 的命令来源；
2. 将 `SquadStrategy` 映射为护送、守位、集中威胁、撤离等有边界的意图；
3. 弓箭从统一 36 格物品栏查找和消耗，删除 NPC 专用弹药语义；
4. 可见敌人、最后所见位置、声音范围和同伴报告进入战术知识；
5. 个人决心与队伍凝聚替代单一伤害倍率式士气；
6. 护送货物、箭矢、伤势、遗失、抢夺和撤回进行统一资产结算；
7. 战后事件写回人物记忆、家庭、行会、议事会、合同和市场。

验收门：

- 没有合同、职位或临时委任时，玩家无法向 NPC 下达命令；
- NPC 能拒绝越过路线、掠夺或无视更高义务的命令；
- 玩家和 NPC 的弓箭消耗使用同一库存规则；
- 未被发现的敌人不会因为服务器真值而出现在普通战术 UI；
- 撤退、投降、救援和护送成功都是正式结果；
- 每个货损、伤势和弹药变化均能追溯并通过守恒测试。

完整规则见 [战斗、指挥与后果](./04-combat-and-command.md)。

## 14. 阶段 11：远方模拟与规模化

目标：在不破坏因果的前提下扩大世界人口和时间跨度。

交付：

- L0-L3 状态与转换；
- 卸载前快照、离线事件推进、加载对账；
- 调度预算、积压监控和管理员诊断；
- 固定种子的跨 LOD 等价测试；
- 远途物流、消息传播和到期契约。

验收门：

- 重复卸载/加载不复制人物、资产或订单；
- 远方结果与同规则细粒度结果方向一致；
- 服务器压力增加时降低频率而不是破坏守恒；
- 对账失败可定位、可冻结、可恢复，不静默覆盖。

## 15. 首个纵向切片

从阶段 0 开始保持同一个可玩故事作为主线，并在后续阶段逐层增加社会、经济与战斗后果：

本节的玛拉故事是产品功能的贯穿示例；可重复自动化与真人验收使用
[`grain_road_lab` 断粮商路实验场](./05-gameplay-validation.md)。两者共享同一组
世界不变量，但测试场不会强迫玩家照着下列叙事顺序行动。

### 场景

铁匠学徒玛拉属于一个三人家庭，对母亲和年幼弟弟承担照料义务。东区粮食短缺、工坊缺木炭；玩家最初只观察到她疲惫并反复望向东区道路。

### 玩家路径

1. 交谈后得知她的家庭责任和工坊需求，但不知道家庭粮仓精确余量；
2. 手持面包直接赠予，玛拉接受并形成一段可解释的共同经历；
3. 玩家查看人物志，看到来源、时间和关系变化，不看到精确内部值；
4. 玛拉愿意用自己的铁锄交换木炭与绿宝石，但不能出售行会所有的铁镐；
5. 双方完成真实库存的原子交换；
6. 玩家与她签订两日护送合同，授权只覆盖北仓—东区路线与紧急防御；
7. 玩家接受议事会运输委托，北仓实际扣除 24 个面包并装入货驴货箱；
8. 林道遇袭时，玩家可在贴身护送、守住路口和带货撤退之间选择；
9. 命令消耗普通背包中的箭，并结算伤势、货损、到货或重新入库；
10. 战后结果分别影响家庭、行会、议事会、私人关系和本地供给；
11. 服务器重启、玩家断线和区块卸载后，物品、合同、知识与事件保持一致。

这条切片覆盖人物、物品栏、权利、认知、递交、交易、契约、社会结构、实体经济、战斗、持久化和 UI，是扩展前的质量门。

## 16. 删除与兼容计划

### 16.1 立即停止新增依赖

- `NpcBase.isOwned()`
- `NpcBase.ownerUUID`
- 招募后 `faction = player`
- `NpcWorkAuthority.PLAYER`
- `bowSlot/arrowSlot`
- `NpcStatsPayload.from(npc)` 完整数据广播式构造
- `NpcTradeRegistry` 生成真实商品
- `tradeIndex` 作为交易身份

### 16.2 兼容期

- 旧方法保留为从 v2 关系投影出的 deprecated 读接口；
- 旧屏幕可在 feature flag 下只读打开，不能提交旧交易；
- 迁移日志明确指出每个旧人物如何转换；
- 至少一个稳定版本后再删除旧字段写入。

### 16.3 不兼容点

以下变化应在版本说明中明确，而不是伪装无缝：

- 商人不再有无限固定货物；
- 玩家不再默认查看被雇 NPC 的完整背包；
- NPC 不再因招募永久改变社会归属；
- 部分旧命令可能超出新合同范围；
- 旧交易配方不会被转换成免费现货。

## 17. 优先级与暂缓项

### P0：正确性

- 人物稳定 ID；
- 36 格物品栏迁移；
- 权利检查；
- 原子转移；
- 服务端知识过滤；
- 真实库存交易；
- 存档与多人并发测试。

### P1：核心体验

- 快捷递交；
- 人物志；
- 合同与命令范围；
- 战术态势、护送与战后后果；
- 家庭生产/消费闭环；
- 可解释 NPC 决策。

### P2：世界深度

- 本地市场；
- 商路与信用；
- 行会、领主关系、法律争议；
- 传闻与文书；
- LOD 规模化。

### 暂缓

- 完整货币铸造与成色模拟；
- 覆盖所有历史时期的社会制度；
- 全语言自然对话生成；
- 全物品重量/容积系统；
- 大规模战争政治，直到资产、授权和远方模拟稳定。

## 18. 每阶段提交要求

每个阶段合并前必须附带：

- 设计差异说明；
- 数据迁移说明；
- 自动化测试与场景录像/日志；
- 多人并发检查；
- 网络披露审计；
- 性能基线；
- 新旧字段使用扫描；
- 已知限制和回滚办法。

## 19. 推荐的下一次实现任务

不要从重画 `NpcCommandScreen` 开始。第一张实现单应是：

> 建立 v2 测试基座和 NPC 36 格个人物品栏适配器，在 feature flag 下完成旧 9 格、弓槽、箭槽的无损迁移；保留运输货舱的独立保管语义，并增加物品总量守恒测试。

它直接回应当前最明确的用户需求，同时为后续财产权、递交和交易建立可靠物理基础。
