# 世界模拟 v2：战斗、指挥与后果

> 状态：设计基线（待实现）  
> 原则：战斗不是独立小游戏，而是人物、授权、物资、地形与信息在高压条件下的共同结果。

## 1. 核心结论

现有战斗代码已经具备士气分层、远程射击、撤退、阵型策略、巡逻边界和运输护送等有价值的部件，但其上层规则仍大量依赖 `ownerUUID` 与“玩家拥有 NPC”。v2 不删除这些战术能力，而是替换它们的授权来源、信息模型和后果结算：

- 玩家能否指挥，来自护送合同、军职、临时委任或被保护关系，不来自所有权；
- 命令表达意图、目标与边界，NPC 依据局部信息执行，不成为遥控单位；
- 伤势、弹药、食物、装备和运输货物都是真实资产或身体状态；
- 玩家只看到其人物能够观察、听到或从同伴获知的战场态势；
- 撤退、投降、救援、俘虏和护送成功都是正式结果，不以“杀光敌人”为唯一胜利；
- 战斗结果写回家庭、合同、经济、名誉和制度，而不是结算后消失。

## 2. 战斗对象

### 2.1 个体 Combatant

个体战斗状态由下列部分组成：

- 身体：伤势、行动能力、疼痛、疲劳与失血；
- 装备：穿戴、手持、耐久和权利来源；
- 补给：箭矢、食物、药品和携带容量；
- 认知：可见敌人、最后已知位置、听到的动静和同伴报告；
- 心理：决心、恐惧、信任、责任与自保倾向；
- 义务：保护谁、守住什么、必须抵达何处、何时可以脱离；
- 权限：可以接收谁在什么范围内的命令。

弓与箭使用玩家相同的普通背包规则。不存在 NPC 专用弹药槽，也不存在无限弹药。AI 选择弹药时仍要检查可达性、所有权与是否允许消耗。

### 2.2 战术单位 Tactical Group

战术单位不是永久阵营标签，而是一段有目的、有成员和有指挥来源的临时或正式组织：

```text
TacticalGroup
├─ members
├─ purpose                 // 护送、守门、巡逻、搜索、撤离
├─ authoritySource         // 合同、职位、委任、紧急请求
├─ commander / coordinator
├─ objective
├─ operatingBoundary
├─ communicationMethod
├─ formationIntent
├─ supplyContext
└─ dissolutionCondition
```

运输护送队在货物交付、合同到期或双方解除约定后解散，不会把成员永久改成玩家阵营。

## 3. 指挥不是直接控制

### 3.1 命令结构

一条命令至少包含：

```text
OrderIntent
├─ issuer
├─ authorityEvidence
├─ objective
├─ priority
├─ target / protectedSubject
├─ operatingBoundary
├─ permittedForce
├─ pursuitLimit
├─ fallbackCondition
├─ expiry
└─ issuedKnowledgeRevision
```

命令状态机：

```text
PROPOSED
  → COMMUNICATED
  → ACKNOWLEDGED / REFUSED / NOT_RECEIVED
  → EXECUTING
  → BLOCKED / COMPLETED / ABANDONED / SUPERSEDED
```

玩家发出命令后，系统不能立即把所有 NPC 的内部目标强制改写。NPC 先判断：

1. 是否收到并理解命令；
2. 发令者是否有对应范围的正当权限；
3. 命令是否违反更高优先级义务或合同边界；
4. 其局部认知是否支持执行；
5. 当前能力、伤势、补给和风险是否允许；
6. 是否需要澄清、拒绝或采用合理替代动作。

### 3.2 首批命令意图

| 意图 | 目标 | 默认边界 | 可合理变通 |
|---|---|---|---|
| 贴身护送 | 保护指定人物或载具 | 不离开保护对象过远，不主动追击 | 临时抢占近处掩体 |
| 守住位置 | 延缓敌人通过某区域 | 留在边界内 | 退到相邻更安全位置 |
| 集中威胁 | 压制已确认的高威胁目标 | 只使用可识别、可触及目标 | 失去目标时改为警戒 |
| 分散火力 | 防止多敌人自由行动 | 不要求平均伤害 | 依据视线和距离分配 |
| 撤离 | 人员或货物退出危险区 | 优先走已知安全路线 | 丢弃无权处置的货物需紧急事由 |
| 搜索 | 查明特定区域 | 不自动攻击未知者 | 遇敌后报告、接触或撤回 |
| 救援 | 接近并带回伤者 | 生命优先 | 无法救援时请求掩护 |

现有 `SquadStrategy` 可作为短期适配层，但不再直接表达永久队伍模式：

- `BALANCED` → 分散火力意图；
- `NEAREST` → 近身威胁优先规则；
- `HIGH_RANK_FIRST` → 已识别高威胁目标；
- `PROTECT_OWNER` → 保护指定主体，删除 owner 语义；
- `HOLD_POSITION` → 守住位置；
- `RETREAT` → 撤离；
- `ESCORT_CONVOY` → 贴身护送指定载具。

## 4. 信息与战争迷雾

服务器保存精确位置、生命、弹药与行为。玩家界面只投影其人物有依据知道的态势：

| 后台真相 | 普通玩家可见表达 |
|---|---|
| 敌人精确坐标持续更新 | 当前可见位置，或带时间的最后所见位置 |
| 士气 63/100 | “仍能协同行动”“开始动摇”等可观察状态 |
| 箭矢 15 | 自己的显示精确值；同伴只显示“箭袋充足/渐空”，除非共同整备 |
| 精确 HP | 明显伤势、动作受限、倒地或由医疗检查确认的结果 |
| AI 当前目标 | 同伴喊话、动作和已确认的命令状态 |
| 草丛内两名敌人 | 听到动静的位置范围，不显示两个单位图标 |

态势界面采用多通道表达：敌我颜色同时配合形状与文字；最后所见位置使用虚线、时间和较低对比；危险提示不能只依靠红绿差异。

## 5. 士气与队伍凝聚

现有 `LOW / SHAKEN / STEADY / INSPIRED / HEROIC` 可以保留为内部兼容层，但 v2 将士气拆成至少两个概念：

- **个人决心**：这个人是否愿意继续冒险；
- **队伍凝聚**：成员是否仍能沟通、相信彼此并协同行动。

影响因素包括：

- 伤亡、包围、疲劳、饥饿和弹药；
- 与同伴的信任和指挥者的正当性；
- 是否理解目标以及目标是否与自身义务一致；
- 附近同伴撤退、英勇行为、救援或背叛；
- 家庭责任、欠薪、曾经履约或被抛弃的记忆。

士气不应只作为伤害倍率。它主要影响沟通延迟、队形保持、风险容忍、救援意愿、投降与撤退阈值。玩家界面使用可观察描述，精确值只进入管理员调试页。

## 6. 战斗与物流

### 6.1 真实消耗

- 射出一支箭，从实际物品堆扣除一支；可回收箭进入现场物品或战利品记录；
- 武器与护甲损耗来自实际使用；
- 食物和药品从有权消耗的库存扣除；
- 运输货物保留货主与订单声明，承运人不能因为持有而出售；
- 载具损坏、丢包、抢夺和弃置都产生明确事件与物品去向。

### 6.2 护送例子

```text
北仓 86 面包
  └─ 出库 24 → 货驴货箱（议事会所有，玩家保管）
       ├─ 安全交付 → 东区市集 +24
       ├─ 混乱遗失 1 → 现场遗失事件；东区 +23
       ├─ 被抢 6 → 劫匪容器 +6；东区 +18
       └─ 带货撤退 → 北仓重新入库 +24；委托未完成
```

无论采用哪个结果，总量、权利和事件都必须对账。

## 7. 伤势、倒地、投降与俘虏

死亡不应是所有战斗失败的默认结果。首批状态：

```text
ABLE → HINDERED → DOWNED → STABILIZED / CAPTURED / DEAD
```

- `HINDERED`：伤势影响移动、瞄准或携带；
- `DOWNED`：无法继续有效战斗，但仍可能获救；
- `STABILIZED`：暂时脱离死亡风险，需要搬运和照料；
- `CAPTURED`：失去行动自由，但仍是完整人物，保留财产主张和社会关系；
- `DEAD`：产生遗体、遗物、继承、家庭与制度后果。

投降是否被接受，取决于对方规则、关系、目标和执行能力。不得把俘虏降格成物品或招募资源。

## 8. 战斗界面

### 8.1 三层信息

1. **场景内提示**：姿态、伤势、喊话、箭袋外观、敌人动作；
2. **即时战术层**：任务、已确认威胁、活动边界、同伴可观察状态与可用命令；
3. **战后记录层**：伤亡、货损、弹药、履约、证词、财产权变化和关系后果。

战术层只展示会改变当前决定的信息。人物完整历史、契约全文和仓库账簿从对应记录页进入，避免把战场变成管理后台。

### 8.2 命令反馈

每个命令必须说明：

- 为什么可用：合同、职位或紧急授权；
- 约束是什么：路线、目标、追击距离、允许使用的武力；
- 是否被收到与接受；
- 若未执行，玩家能知道的原因；
- 可观察结果，而非 AI 隐藏分值。

例：

```text
贴身护送
来源：两日护送合同
边界：北仓—东区路线；不追击
状态：玛拉已确认
结果：她移动到货驴侧后方，保持射界
```

## 9. 对现有代码的改造

### 9.1 `CommandTactics`

- 将 `owner` 改为 `protectedSubject`、`issuer` 与 `authorityEvidence`；
- 40 格响应范围改为命令通信与作战边界配置，不作为所有权半径；
- `intentUntilTick` 保留为短期承诺，但与订单状态机连接；
- 目标选择只使用 NPC 已知威胁，不读取玩家知道而 NPC 不知道的目标。

### 9.2 `NpcCombatGoal`

- `ownerAttacked / ownerAttacking` 改为受保护对象、合同目标或合法指挥来源；
- 自卫和复仇仍可成为独立动机，不需要玩家授权；
- 巡逻边界升级为通用 `OperatingBoundary`；
- 目标失去视线后使用最后所见知识，不持续跟踪后台坐标。

### 9.3 `NpcMoraleState`

- 内部等级继续用于迁移；
- 新增个人决心、队伍凝聚和触发事件；
- 伤害倍率逐步移除，改由行为选择与动作质量表达；
- 投影层只发送可观察描述与来源。

### 9.4 `ConvoyEscortGoal`

- 货物来自 `LogisticsOrderRecord` 绑定的真实容器；
- 护送目标、路线和处置边界来自合同；
- 运输者死亡、载具损坏和抢夺分别结算，不一律把货物直接掉落；
- 到货同时验证订单修订、容器内容、目的地权限和接收容量。

### 9.5 `CommandWandScreen`

- 不再作为万能管理屏；
- 拆为战术意图条、任务态势与战后记录；
- 只有授权范围内的命令出现；
- 精确士气、AI 目标和完整库存移入管理员审查页。

## 10. 测试场景

首批必须自动化的战斗场景：

1. 没有合同的玩家不能向玛拉发出“护送”命令；
2. 有护送合同但要求离开路线抢劫时，玛拉拒绝且合同仍有效；
3. 射击消耗普通背包中的箭，耗尽后不能继续远程攻击；
4. 守路口导致 5 支箭消耗和轻伤，库存与身体状态同时更新；
5. 贴身护送遗失 1 个面包时，总量在北仓、货箱、东区和损失事件之间守恒；
6. 带货撤退后 24 个面包重新入库，运输订单标记未完成；
7. 未看见第二名敌人的 NPC 不因服务器真值自动瞄准；
8. 玩家断线后，NPC 依据合同、风险和最近已确认意图决定继续、等待或撤退；
9. 区块卸载后以事件级模拟结算，重新加载时货物、伤势和订单结果一致；
10. 战后事件分别更新家庭、行会、议事会和私人关系，不写成一个全局好感值。

## 11. 演示验收

演示中的“粮荒前的三天”必须做到：

- 人物页能看见玛拉的有限信息、真实交易物和合同范围；
- 社会页能看见家庭、行会、聚落与玩家约定的重叠关系；
- 生计页能看见北仓、运输货箱和东区市集的物资流；
- 行动页能看见有限态势、合同授权、三种命令意图和可观察状态；
- 选择命令后，货物、箭矢、伤势、履约和关系结果同时更新；
- 后台真相页可核对精确数据，但正式视图不泄露这些字段。
