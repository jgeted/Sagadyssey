# 社会系统单次多人验收清单

这份清单用于在代码构建通过后，集中启动一次 Minecraft 完成验收，避免开发期间反复重启客户端。建议使用一台服务器、两个非 OP 玩家 A/B，并保留一个 OP 账号执行准备命令。

## 启动前（不启动游戏）

1. 执行 `./gradlew verifySocialSystem build`。
2. 确认两个客户端安装相同构建；当前网络协议为 13，旧客户端应被拒绝连接。
3. 备份测试世界。测试包含永久角色死亡和物理库存消耗，不应在唯一正式存档中直接执行。

## 快速单人验收：NPC、交易界面与 R 键势力界面

这组步骤只需一个允许作弊的超平坦世界，优先执行；它能在几分钟内确认本轮界面和阵营交易规则是否真的接到了服务端。

1. 执行 `/time set day` 和 `/gamerule doDaylightCycle false`。
2. 执行 `/saga scenario generate trader_lab`，用 `/saga scenario status` 等待生成完成，再执行 `/saga scenario verify`。
3. 执行 `/give @s minecraft:emerald 64` 与 `/give @s minecraft:wheat 64`。空手右键“实验商人”，确认先打开 NPC 认知界面，而不是直接递交物品。
4. 选择“提出交易”。分别把绿宝石和小麦加入左侧报价，再把纸和书加入右侧报价；逐行测试选中、加减数量和移除。提交后四种物品必须一次性全部交换，不能只成交其中一行。
5. 贴近 NPC 再次打开界面，确认模型不会穿透不透明背景，身份、外貌和所属信息没有异常省略号。
6. 按 `R`，确认势力名册、声望条、交易门槛、招募条件与已知外交关系均可见；点击左侧不同势力应切换右侧详情。
7. 执行 `/sagadyssey faction set @s sagadyssey:merchant_guild -40`，重新按 `R`，应显示“冷淡”和 `120%` 报价门槛；交易仍可打开，但边缘报价应更容易被要求加价。
8. 执行 `/sagadyssey faction set @s sagadyssey:merchant_guild -80`，关闭并重新打开 NPC 界面；“提出交易”应消失，直接伪造开单请求也会被服务端拒绝。
9. 执行 `/sagadyssey faction set @s sagadyssey:merchant_guild 30`，应显示“尊敬”和 `90%` 报价门槛；最后用 `/sagadyssey faction set @s sagadyssey:merchant_guild 0` 恢复中立。

## 0. 固定世界部署

1. 在空白超平坦世界执行 `/saga scenario preview small_realm`，确认蓝色边界、五个金色聚落中心和两块绿色 9×9 农田工作区。
2. 执行 `/saga scenario generate small_realm`，期间用 `/saga scenario status` 查看阶段，确认服务器没有长时间卡死。
3. 生成完成后检查五个聚落、道路、两块中心水源 9×9 农田、16 座建筑、5 个实体仓库和 20 名居民；世界内不得残留结构方块或白色模板边框。
4. 执行 `/saga scenario verify`，应报告固定世界验收通过；未加载 NPC 只允许显示黄色提示，不能出现结构性错误。
5. 在生成中途保存退出一次，再次启动后任务应继续且不重复生成聚落、仓库或 NPC。
6. 执行 `/saga audit`，制度统治阵营不应再产生“王位无持有人但未标记空缺”。
7. 在备份测试世界中破坏一个农田围栏，确认 `verify` 能发现问题；执行 `/saga scenario repair confirm` 后再次验收。
8. 招募一名固定场景 NPC 后再次修复，确认其玩家归属、经验、身份和阵营没有被修复流程重置；已经发生变化的政治关系也不能回到初始值。

## 1. 多人交互与隐私

1. A、B 各自招募 NPC；两人站在同一区域，不点击任何 NPC，观察 5 分钟：不应自行弹出 NPC UI。
2. A 打开自己的 NPC 界面并下达跟随/工作/转职；B 不得控制、转职、打开装备栏或解散该 NPC。
3. A 创建物流订单。只有 A 能看到所属运输者头顶的精确物品、数量和货舱信息；B 不应看到这段私人反馈。
4. A/B 互相攻击：受攻击玩家同集团的战斗 NPC 应优先响应玩家威胁，不应继续追逐墙后的无关怪物。
5. 跟随玩家穿过有遮挡的区域，检查 NPC 不因透视选中不可达怪物而抽搐。

## 2. 指挥杖、编组与护送

1. 用指挥杖框选不同职业，确认轮廓、颜色和选择范围反馈可见。
2. 建立两个小队，执行升降等级、拆分、合并和切换战术；重新登录后状态仍保留。
3. 将运输者与战士/弓箭手/重装放入同一小队，选择“护送运输”，再让运输者工作。
4. 护卫应围绕正在执行订单的运输者移动；运输者遇袭时，同小队护卫应接战，物流实体物品不能凭空消失。
5. 集团“工作”命令应覆盖工人、农民、铁匠、诗人、医师、商人和运输者；工作区角点仍只作用于工人和农民。

## 3. 生产、仓储、运输、消费

1. 用 `/saga settlement create village kingdom <名称>` 建立两个聚落，在真实箱子/木桶上分别执行 `/saga logistics register <名称>`。
2. 农民/工人工作产出达到阈值后，应把可储存产物送入已登记仓库；工具和生产补给不应被错误清空。
3. 检查麦田村两名初始农民：调试信息必须显示具体范围；农民不得进入马场翻地或播种。
4. 用 `/saga logistics order <起点仓库UUID> <终点仓库UUID> minecraft:wheat 32` 建立订单，再用 `/saga logistics orders` 检查状态。
5. 箱子中的 32 个小麦应由运输者实际取走并实际放入终点；区块未加载时不得瞬移或强制加载。
6. 跨过一个游戏日后执行 `/saga economy`：人口、所需口粮、已消费口粮和连续缺粮天数应更新；缺粮只能消耗真实仓库物资并影响士气。

## 4. 政治、继承和死亡

1. OP 用 `/saga politics appoint kingdom <玩家>` 任命君主；君主使用 `/saga politics grant <聚落UUID> <玩家>` 授予领地。
2. 封臣执行 `/saga politics swear <玩家>`，持有头衔者执行 `/saga politics heir <玩家>`；用 `/saga politics realm` 检查关系。
3. 对一个有足够绿宝石的角色制造致死伤害：应支付代价并假死返回，身份不丢失。
4. 移除其赎命资源后再次死亡：旧角色永久死亡；指定继承人得到王位/领地。复活后的新角色不得继承旧身份、NPC、集团或声望。
5. 继承人在线时应立即更新身份；离线时应在下次登录自动校正。

## 5. 动态世界、性能与存档

1. 用 `/saga world events` 查看事件；OP 可用 `/saga world force_event famine <聚落UUID>` 等命令集中测试饥荒、瘟疫、边境袭击、停战、集市和继承危机。
2. 确认事件只影响已加载聚落，饥荒提高真实口粮需求，事件开始/结束进入 `/saga world history`。
3. 同时让至少 20 名 NPC 跟随或工作、4 名运输者运货、12 名护卫执行护送，观察 TPS 和路径抖动。
4. 执行 `/saga audit`，结果应为“社会系统审计通过”。
5. 正常保存退出并仅重启一次服务器，重新检查 `/saga audit`、聚落、头衔、订单、库存、事件和当前人物绑定。

## 通过标准

- 无越权 UI、远程控制、跨玩家 NPC 继承或私人物流信息泄露。
- 无虚拟生成/删除库存；运输中断不会把账面货物当作已交付。
- 政治、角色、聚落、物流、事件之间没有悬空引用。
- 压力场景无持续 TPS 崩落、护送全员同步寻路尖峰或跟随抽搐。
